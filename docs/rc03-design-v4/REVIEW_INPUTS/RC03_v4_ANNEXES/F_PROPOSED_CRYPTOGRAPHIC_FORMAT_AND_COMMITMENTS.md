# Annex F — Concrete protection and portable-container proposal

Version `4.0.0-draft`. **Unselected integration proposal; no adoption or implementation authorization.** Existing cryptographic library constructions are used as proposed building blocks; no replacement cipher, KDF or ratchet is specified. Independent Cryptography and external human integration review are prerequisites to adopting this format/key hierarchy, sensitive reliance and recovery-dependent retirement. [B](B_LIFECYCLE_REVISIONS_AND_COMMITS.md), [C](C_OPERATION_AND_EFFECT_TABLES.md), [D](D_MIGRATION_AND_DESTRUCTION_RESTART_TABLES.md) and [E](E_DESCRIPTORS_AND_COMPATIBILITY.md) supply semantic schemas.

## F1 — Canonical records and key hierarchy

Proposed canonical encoding `C(x)` is RFC8949 core deterministic CBOR (§4.2.1): shortest definite lengths/integers, map keys sorted by bytewise lexicographic order of their deterministic encodings, never the alternate length-first convention. No tags, floats, undefined, indefinite lengths, duplicate keys, unknown fields or noncanonical equivalents. Map keys are exact ASCII field names from the closed schemas; enums are exact text; text valid UTF-8 with no implicit normalization. Arrays preserve declared semantic order; sets explicitly sort as below. Internal U64/Sat/revisions are CBOR unsigned integers, not decimal text; IPC decimal strings are range-checked then converted losslessly. IDs decode to16-byte bstr, H to32-byte bstr, cryptographic keys/scripts/data are bstr, booleans/null as declared. Every optional map field is **absent** when not present, not encoded null unless schema explicitly permits null. Code/schema notation has no effect on these wire types. Decoder re-encoding equality is checked within bounded resources before accepting canonical input. [RFC8949](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2.1).

`RecordPlain=[1,type:tstr,id:bstr16,revision:uint,context,body]`; `context=[profile:bstr16,wallet:bstr16,generation:uint,network:tstr,purpose:tstr]`. Profile-wide records use generation0xffffffff and wallet=manifest wallet ID; actual generation allocation excludes0xffffffff. Lifecycle context is `[installation:bstr16,slotEpoch:uint,'installation-lifecycle']`, with separate record class/key. Body must match the referenced closed B/C/D/E/F schema. Profile-wide records cannot be used as per-output key records. Purpose equals registered type purpose, not a caller string.

`D(label,x)=SHA256(C([label:tstr,x]))`; labels literal `finney.rc03.record.v1`, `finney.rc03.members.v1`, `finney.rc03.intent.v1`, `finney.rc03.output-binding.v1`, `finney.rc03.coverage.v1`, `finney.rc03.artifact.v1`, `finney.rc03.scope.v1`. Record Ref digest is D(record,RecordPlain), **not local ciphertext digest**. Membership page is `{schema:1,page:ID,entries:[[type,id,revision,recordDigest]...]}` sorted by raw UTF-8 type bytes then raw ID bytes, unique `(type,id)`, <=1024 entries and256KiB; pages are sorted by first membership key, disjoint and complete. Manifest references page plaintext digests. Membership excludes the manifest itself and membership-page nodes, which are anchored by head and manifest respectively, preventing recursive self-hashing. Duplicate/missing/extra committed membership fails. References plus object lookup keys use expected profile/type/id/revision, never an arbitrary storage path. Intent digest is D(intent,exact Intent); aliases sort by network/txid bytes/vout numeric; effect dependency sets by raw ID; original input/output/encounter/transaction order never sorted away. Type-purpose mapping is exact: root -> legacy-wallet-root, scalar -> output-recovery, every other profile RecordType -> its identical type token. A BoundKeyRef spending/identity purpose is additionally checked against that record's allowed use; it never rewrites the stored purpose. Root/output/scalar context generation is its actual generation; profile-wide catalogue/manifest/policy/membership pages use the reserved profile-wide value; all other records carry their owning generation or the explicit profile-wide value according to the declared body scope.

Proposed Windows chain of protection:

1. Generate independent random32-byte `KL` per installation and `KP` per profile using OS-backed CSPRNG. DPAPI/current-user via pinned Electron safeStorage wraps **separate** canonical anchors encoded as base64 text: `[1,'life',installationId,KL]` and `[1,'profile',installationId,profileId,KP]`. Validate embedded context against selected installation slot after unwrap; exact bytes/length only. Wrong-account/unavailable/corrupt refuses. No plaintext fallback. Anchors held in distinct lifecycle/profile storage domains. Protected expected installation/slot comes from authenticated lifecycle head, not a replaceable record's self-description. Initial installation identity depends on controlled package mapping and successful absence probe; same-user host compromise and complete self-consistent rollback remain outside claims.
2. Standard HKDF-SHA256 (RFC5869), IKM=KP, salt=profileId16, info=ASCII `finney.rc03.profile.record-aead.v1`, output32 gives `Krecord`. Separate info `finney.rc03.profile.head-mac.v1` gives `Khead`; `finney.rc03.profile.journal-mac.v1` gives `Kjournal`. KL with salt=installationId and info `finney.rc03.life.head-mac.v1` / `finney.rc03.life.record-mac.v1` derives lifecycle keys. No wallet/identity scalar or mnemonic is a storage/backup key. Standard Node crypto HKDF/HMAC/AES-GCM in pinned packaged runtime is the proposal; runtime/OpenSSL versions must be recorded. [RFC5869](https://www.rfc-editor.org/rfc/rfc5869.html).
3. Profile record envelope `[1,context,type,id,revision,nonce:bstr12,ciphertext:bstr,tag:bstr16]`; AES-256-GCM Krecord; AAD exactly `C(['finney.rc03.record-aead.v1',1,context,type,id,revision])`; plaintext exactly C(RecordPlain). Fresh OS-random96-bit nonce every encryption, including retries that reencrypt. Exact persisted-envelope resend is not re-encryption. Profile lifetime maximum2^24 encryptions then typed resource block pending separately reviewed rekey; active key nonce ledger rejects observed duplicates, RNG error aborts. Random-nonce residual collision risk needs specialist acceptance; ledger is not a full-store rollback defence. Tag length16 required, no truncated tag or alternate mode. After decrypt verify inner matches outer and expected committed Ref digest.
4. Authenticated head `[1,installationId,profileId,revision,manifestObjectId,manifestDigest,commitId,mac]`, mac=HMAC-SHA256(Khead,C(all preceding fields)). Journal MAC=HMAC-SHA256(Kjournal,C(['finney.rc03.commit.v1',Commit])) over complete expected/staged/prior/value references B4. Membership pages are encrypted profile records reached from this authenticated manifest. Digest-only replaceable head is rejected. Prepared journal authentication cannot promote staged values absent atomic committed head/result.
5. L records use `[1,installationId,slotEpoch,type,id,revision,body,mac]`, HMAC with lifecycle-record key over preceding fields; L head separately authenticated with lifecycle-head key. Only nonsecret D4 metadata lives there, no KP. Atomic sync L head/member update anchors expected lifecycle revisions. Deleting KP/P cannot erase KL/L. Whole L+anchor valid rollback remains a stated limit. Installation identity or anchor substitution from another installation conflicts; loss never generates a replacement key over residue.

Local encryption keys/DPAPI blobs are never in portable backup. Export canonical semantic records and membership; restore validates original-context digests, then creates a separately bound inactive candidate with freshly generated local keys. Profile/wallet/generation IDs and every reference are remapped consistently only after full validation, with `restoreSource={originalProfile,originalWallet,originalGeneration,originalRecordDigest,artifactDigest}` retained in a protected provenance table. Immutable transaction/message bytes, original replay bindings and operation origins are unchanged. Recompute local record/coverage digests after rebind; original digest checks precede remap. No imported approvals become executable. A copied protected profile is unsupported acquisition, not automatic continuation.

## F2 — P4 exact library and framing proposal

Proposed implementation binding: **libsodium.js tag0.8.4, sumo build, libsodium core1.0.22**, `crypto_secretstream_xchacha20poly1305_*` and `crypto_pwhash(...ALG_ARGON2ID13)`. Both wrapper and compiled core artifacts must be pinned and integrity-recorded in a separately authorized dependency change; assert loaded core version and constants, prohibit semver drift/alternate fallback. No package installed here; npm archive/ABI/runtime provenance unverified. Independent consumer proposal uses upstream C libsodium1.0.22. Upstream release/source evidence establishes a maintained candidate, not its acceptability in Finney. [Binding release](https://github.com/jedisct1/libsodium.js/releases/tag/0.8.4), [core release](https://github.com/jedisct1/libsodium/releases/tag/1.0.22-RELEASE), [binding build](https://raw.githubusercontent.com/jedisct1/libsodium.js/0.8.4/Makefile).

Suite `1` means exactly this stream construction; KDF `1` means Argon2id1.3,32-byte output,16-byte salt, lanes1,ops3,mem67108864 bytes. Fixed tuple is deliberate: **no range and no imported lanes2–4**, no ALG_DEFAULT. Core wrapper uses one lane; this tuple is not the RFC four-lane profile. Parser checks constants before KDF. The alternative to selecting this proposal is to keep portable operations disabled and commission another exact reviewed established-container profile; there is no implicit candidate fallback. [Pinned KDF source](https://raw.githubusercontent.com/jedisct1/libsodium/1.0.22-RELEASE/src/libsodium/crypto_pwhash/argon2/pwhash_argon2id.c), [password API](https://doc.libsodium.org/password_hashing/default_phf).

All fixed numeric fields are unsigned **big endian**. Header Hdr exactly64 bytes:

| Offset | Width | Value |
|---:|---:|---|
|0|4|ASCII FNYR (`464e5952`) |
|4|2|format4 |
|6|2|suite1 |
|8|2|KDF1 |
|10|2|flags0 for P-min; flags1 for selected P-pad F3; no compression or other extensions |
|12|4|memory bytes67108864 |
|16|4|opslimit3 |
|20|1|lanes1 |
|21|1|credential encoding1 (F3) |
|22|2|reserved0 |
|24|16|fresh random salt |
|40|24|library-generated secretstream header |

No profile/wallet/network/revision/timestamp/count/commitment in clear header. File after Hdr: repeated `uint32be ciphertextLength || ciphertext`, no other fields. Each nonfinal frame has exactly65536 plaintext bytes, ciphertext65553; final has0..65535 plaintext bytes, ciphertext17..65552. For payload multiple65536, emit empty FINAL; empty payload never semantically valid. Exactly one final frame, immediate EOF after it. Maximum2048 nonfinal plus one final, **total plaintext <=134217728 bytes**; maximum file134260821 bytes (64 +134217728 +2049*21). Precheck file size/count/length and cumulative counters without overflow. Require secretstream tag0 MESSAGE on nonfinal and tag3 FINAL on last; PUSH/REKEY explicit tags rejected (library internal rekey remains internal). Frame ordinal begins0; AAD for each push/pull exactly `Hdr || uint32be ordinal || uint32be ciphertextLength`. No manual nonce or stream-state resume. Length prefix is authenticated through AAD; missing/extra/reordered/duplicated frames or trailing bytes reject. Library constants KEYBYTES32,HEADERBYTES24,ABYTES17 asserted. [Library stream API](https://doc.libsodium.org/secret-key_cryptography/secretstream), [pinned constants](https://raw.githubusercontent.com/jedisct1/libsodium/1.0.22-RELEASE/src/libsodium/include/sodium/crypto_secretstream_xchacha20poly1305.h).

Key schedule: credential bytes+salt -> exact crypto_pwhash output32 -> **secretstream key only**. No reuse as local storage, wallet or HMAC key. Library init_push supplies fresh header/nonce internally. Every fresh export, including retry after changed/unknown plaintext, obtains fresh salt and fresh stream state; RNG failure aborts before final artifact. Retransmit already finalized exact ciphertext only as same artifact. Password change generates a new artifact and cannot revoke copied old artifacts or leaked signing keys. Format/inner/suite unknown -> UNSUPPORTED with no downgrade/reinterpretation.

## F3 — Pending credential and privacy alternatives

Both credential alternatives share encoding1: valid UTF-8 bytes of entered Unicode string **without normalization, case folding, trimming or newline conversion**; reject NUL/unpaired surrogates; preserve all permitted whitespace and compare confirmation byte-for-byte. BIP39 normalization is unrelated. Import min1/max1024 bytes to recover supported historical P4 artifacts; export policy stricter below. Trusted channel only, no logging/string-copy erasure guarantee.

Credential G: main generates32 random bytes, displays64 lowercase hex characters in trusted UI, password bytes are those64 ASCII characters; confirmation before export, independent of mnemonic. Credential H: user-entered passphrase16..1024 UTF-8 bytes, twice confirmed with visible whitespace/encoding notice and offline-guessing warning; no claim length guarantees entropy. Either uses same exact KDF; weak human input never causes lower costs. Owner must choose G or H, storage/transfer guidance and recovery-device envelope. Generated secret itself is never in clear header or clipboard by default.

Privacy alternative P-min uses exact F2 header and no padding: observers see recognizable format/suite/KDF, artifact byte length and equality of identical copied files; fresh random exports lack deliberate stable identifiers. Encrypted payload retains original IDs/time as needed. P-pad uses **same suite** but flags1 and an encrypted outer payload `{schema:1,data:bstr,pad:bstr}`; data is canonical F4 bytes, padding OS-random, total plaintext rounded up to next1MiB (including CBOR wrapper; choose unique minimal pad length satisfying exact total, reject nonminimal/nonmultiple). Max128MiB including wrapper/pad. Inner data length/depth charged budgets; validate after authentication. Flag1 is a distinct owner-selectable format policy, not accepted when selected policy requires flags0; parser understands both only if explicitly allowlisted. P-pad conceals fine size, leaks1MiB bucket and format; it does not guarantee anonymity/unlinkability. Neither includes clear stable IDs/coverage digests. Credential policy and padding selection pending; no export/qualification before choice. Tests compare repeated synthetic exports and credential changes. Transport/file names/OS metadata may leak independently.

## F4 — Complete semantic payload

Payload is a single closed deterministic-CBOR map:

`{format:4,suite:1,payloadSchema:1,credentialEncoding:1,profile:ProfileSnapshot,catalogue:Generation[],records:RecordPlain[],operations:Operation[],effects:Effect[],reservations:Reservation[],replay:Replay[],tombstones:Tombstone[],policies:Policy[],coverage:Coverage}`.

`ProfileSnapshot={profile:ID,wallet:ID,network:Network,epoch:U64,active:U32|null,originSchema:1,derivation:'finney-legacy-899-145-v1',createdUtcMs:U64}`. Generation B3, Output/Scalar/Descriptor/Quarantine E1/E2, root/candidate B, migration/content-retention/retirement D, operation/effect/replay C. `Reservation={schema:1,network:Network,txid:H,vout:U32,operation:ID,generation:U32,state:'reserved'|'possibly-spent'|'spent-retained',artifactDigest:H|null}`. `Policy={schema:1,id:ID,revision:U64,selection:map}` where selection has exactly keys `ceremony,secretChannel,continuation,publication,credential,padding,unresolvedCoverage,availability,retention,pendingDeletion,remoteDeletion,cancellation,provider,backend,durability,migration,oldClient,residualCopies,freshness,deletionClaim,compromise,retainedObservation,uncertainty,toolchain,externalLaunch`; values are selected option tokens in G5, no arbitrary nested fields. Unselected token is permissible evidence but blocks dependent restore qualification. Export contains policies as historical data, not acceptance on new installation.

`Coverage={schema:1,profile:ID,epoch:U64,policyDigest:H,entries:[[category:tstr,id:bstr,semanticDigest:bstr32]...],digest:H,complete:boolean}`; categories closed to catalogue/root/output/scalar/quarantine/operation/effect/reservation/replay/tombstone/retention/policy. Sort by raw category bytes then id bytes, unique; every record participates exactly once in owning category. No backup artifact records/live grants/OS anchors/cached projections/lifecycle-MAC keys. Immutable supporting raw evidence and exact pending final artifacts are included as referenced bytes/chunks in records/operations, all refs must resolve; no external relay/path lookup. Duplicate semantic records in named collections and records array are prohibited: records holds root/output/scalar/quarantine/candidate/candidate-validation/migration/retention/retirement/observation; dedicated collections hold their named types. Any included non-recovery record must be classified or rejected, never ignored. `Observation={schema:1,id:ID,profile:ID,generation:U32,source:ID,sequence:U64,rawDigest:H,raw:bytes,admission:'unadmitted'|'validated'|'conflicting'}`; unadmitted custody-bearing observations prevent completeness until resolved. Candidate/migration/retirement state is included as recovery evidence, never resumed automatically on import; semantic coverage includes their recovery-bearing contents under catalogue/retention categories. Unknown fields/types/noncritical extensions reject in v1.

Profile ID and network are encrypted-only fields; their consistency is checked across payload records, not against nonexistent clear-header identifiers. Format/suite/credentialEncoding must equal authenticated header fields. Every root/output/scalar and operation generation exists in catalogue; active unique; every reservation maps actual operation/output; exact bytes/IDs recomputed; descriptor/fallback script and alias evidence revalidated. Recoverability boolean/complete flag never trusted without recomputation. Restore prohibits installing executable approval/continuation and obtains local deployment/policy selection separately. Output gaps, unknown schema, conflict/quarantine or omitted dependency -> incomplete candidate only, no complete qualification or source retirement. The records collection also includes referenced inventory-page/artifact-chunk/effect-audit-page/provenance records from B3/C1; membership pages and local manifest are reconstructed from verified semantic records, not imported as local authentication roots. Provenance body is `{schema:1,id:ID,originalProfile:ID,originalWallet:ID,originalGeneration:U32,originalRecordDigest:H,artifactDigest:H}`. Recovery-bearing source chunks and provenance contribute under retention in CoverageView; they cannot be omitted because they lack a named dedicated array.

## F5 — Parser, staging and resource limits

Before KDF: constant64-byte header read, file<=134260821, exact fixed tuple/version/flags, one active/one queued installation job, user consent and resource reservation. No attacker-controlled memory allocation based on unchecked header lengths. KDF memory64MiB; crypto worker hard budget256MiB, decoder live object budget64MiB, main/import-accounted aggregate384MiB (including buffers/IPC copies); streaming decode/page insertion avoids retaining full128MiB plaintext. CBOR depth16, map fields<=64, total nodes<=2000000, individual text<=65536 except stored raw<=1MiB,100000 outputs/16generations/4096unresolved ops under A5. Byte and count budgets compose, not independent permissions to allocate all maxima at once. Protected import staging<=256MiB; authority admission/quota remains A5. No compression/decompression bombs.

KDF CPU deadline10s and total import/export120s of active work, IO deadline30s per bounded request; cancellation terminates isolated worker<=2s at safe boundary, no admitted authority. Timings are proposed device acceptance limits, not measured promises; slow devices return resource/timeout and retain source, never reduce costs. Worker processes have no network/ordinary renderer access and receive only scoped input; memory failure returns LIMIT/UNAVAILABLE. Pre-authenticated decrypted chunks never project or activate. Stream into candidate encrypted staging under fresh local key, never plaintext file. Only after FINAL+EOF, canonical parse and complete semantic validation may B2 mark validated. Failed authentication/cancel records disposable candidate cleanup; no active overwrite, no reservation release. Preserve source and classification if cleanup fails.

## F6 — Stable qualification and retirement recheck

`CoverageView` includes exact semantic catalogue/generation states, root/derivation/discovery data, all known output/scalar/quarantine/provenance, immutable intents/final bytes, semantic effect evidence/attempt budget/uncertainty, reservations, durable replay bindings, tombstones/retention and relevant selected policy. It **excludes** global manifest revision, local ciphertext/nonces, projection/cache, scan timestamps, export job/cursor/file name, artifact catalogue, verification timestamps/results and backup qualification metadata. Relevant record revisions themselves are excluded if body is semantically unchanged; fields retained by above list are canonically hashed. Epoch and catalogue lifecycle ARE relevant. Coverage entries use semantic digests of these exact projections; `coverageDigest=D(coverage,[profile,epoch,policyDigest,entries])`. Any genuine added/changed/removed recovery-bearing semantic member stales it; identical-body re-encryption/qualification bookkeeping does not. Attempts/late evidence that alter uncertainty or remaining delivery authority stale; diagnostic duplicate-receipt timestamp alone does not.

SnapshotToken records head revision solely for consistent reads/pinning, separate from coverage comparison. Writer freezes/pins immutable members, computes required coverage, then export may release writer while pinned snapshot persists. Actual final file is encrypted, flushed with selected filesystem barrier, atomically published by main on same volume and directory durability established per G. Artifact hash is SHA256 of **entire final container bytes** (raw-file digest, not D domain wrapper). `Qualification={schema:1,id:ID,artifactDigest:H,byteLength:U64,coverageDigest:H,policyDigest:H,verification:'pending'|'complete'|'failed',verifiedFixtureVersion:U32,locationHandle:ID,stale:boolean}` is a protected backup record **excluded from CoverageView**. First successful verification commit therefore cannot invalidate itself. Caller cannot set verification/coverage/stale flags.

Verifier independently decrypts exact finalized file, checks all refs/counts/context, reconstructs every required known script and verifies synthetic signing ability in isolated test context, compares recomputed required coverage to frozen snapshot. Operational restore never automatically signs a real transaction. Qualification acceptance also requires planned fresh-profile offline recovery evidence without original OS key or relay; mnemonic backup alone cannot qualify. Interrupted write/rename/ACK creates unqualified artifact until actual-byte reconciliation. Recording digest alone is not durability or coverage evidence.

At retirement, D2 holds writer fence and stable artifact read handle, reauthenticates/recomputes actual bytes and current CoverageView, checks artifact availability and evidence class, then commits exact retirement scope. Selected availability alternatives: stable local qualified artifact on separately retained media/domain, or user-held removable artifact mounted/read/authenticated now with explicit custody acknowledgement. Neither promises future media survival. Owner may choose inclusive unresolved artifacts or block qualification while unresolved; no interpretation discards them. Post-qualification receipt/output/effect/reservation/tombstone/retention/policy change invalidates; pending event drained before final irreversible point. No-op bookkeeping does not. Full valid snapshot rollback and future unseen outputs remain outside freshness/recovery claims.
