# Annex C — Intent, effects, replay and recovery authorization

Version `5.0.0-draft`; proposed only. [A](A_IPC_SCHEMAS_AND_LIMITS.md) defines admission; [B](B_LIFECYCLE_REVISIONS_AND_COMMITS.md) defines durable authority; [F](F_PROPOSED_CRYPTOGRAPHIC_FORMAT_AND_COMMITMENTS.md) defines encoding/authentication. All internal records below are protected graph members.

## C1 — Intent and transaction authorization

`Intent={schema:1,operation:ID,kind:'xec-send'|'stamp-message'|'profile-publication'|'registry-publication'|'forum-publication',profile:ID,wallet:ID,generation:U32,network:Network,originRequest:RequestBinding,recipient:bytes,content:bytes,outputs:[{script:bytes<=512,value:Sat,role:'recipient'|'stamp'|'change'|'burn'}],inputs:[{output:ID,ref:Ref,txid:H,vout:U32,value:Sat,script:bytes}],fee:Sat,feeCeiling:Sat,changeRefs:Ref[],wireVersion:U32,transportPlan:TransportTarget[],policyDigest:H}`. Up to256 inputs/outputs combined,16 transactions,32 effects, A5 byte totals. Content is exact accepted message/publication text encoded by existing codec, not arbitrary signable bytes. Recipient key/address/network correspondence is validated in main. No input or change path is chosen by renderer. Main deterministically constructs unsigned plan and summary from owned inventory; input total-output total equals fee with checked integer arithmetic, no negative/overflow, fee<=explicit displayed ceiling, every change script derived from this wallet's preserved change branch and committed before use. Non-payment publication has zero inputs/fee but still requires consent. Unsupported burn/formats fail before approval, never fallback to legacy automatic HTTP402 payment.

`RequestBinding={installation:ID,profile:ID,sessionEpoch:U64,request:ID,method:Method,argsDigest:H,callerDigest:H}`. Main assigns sessionEpoch at opening the caller document; payload cannot mint epoch. Persist mapping and operation in the same B4 commit. `Operation={schema:1,id:ID,intent:Intent,intentHash:H,immutableVersion:1,approval:{state:'none'|'issued'|'consumed'|'aborted',id:ID|null,summaryHash:H|null,consumeCommit:ID|null},reservations:Ref[],artifact:Artifact|null,effects:Ref[],recoveryPolicy:'unselected'|'fresh-consent'|'exact-delivery',aggregate:OperationState,revision:U64}`. Approval expiry and live-grant material are not resurrectable authority in backups. `Artifact={id:ID,intentHash:H,transactions:[{txid:H,bytes:Blob}],messages:[{id:H,bytes:Blob}],publications:[{id:H,bytes:Blob}],digest:H,commit:ID}`. `Blob={length:U32,digest:H,chunks:Ref[<=128]}`; each artifact-chunk body is `{schema:1,id:ID,artifact:ID,part:U32,ordinal:U32,data:bytes<=65536}`. Every chunk but final is exactly65536 bytes; concatenated bytes match length/SHA256, unique ordinals from0 with no gap, max8MiB aggregate per artifact. Raw source evidence uses this same protected byte-container type with its own artifact ID, never a signing purpose. Main recomputes IDs/digest from exact final bytes. No altered input/fee/recipient/content after approval; any such change requires a new prepared intent and fresh trusted approval, preserving prior uncertain obligations.

## C2 — Effect schema and reducer

Operation additionally has required `continuation:Continuation|null` using C4; null for unselected/fresh-consent. Its remaining-attempt/expiry/revocation state is protected semantic recovery data. Portable restore preserves it as historical evidence and forces nonexecutable state; it cannot be used to mint grants on the new installation.

Every Effect also has required `auditPages:Ref[<=4096]`, initially empty. Each Ref has type `effect-audit-page` and body `{schema:1,id:ID,operation:ID,effect:ID,ordinal:U32,attempts:Attempt[<=64],evidence:Evidence[<=256]}`, <=256KiB, immutable after attachment. Pages concatenate in ordinal order before current arrays; attempt/evidence IDs are unique across the full history. Moving records to a page and removing them from current arrays is one B4 commit, and never resets a reducer or replay count. At the declared page/operation/storage limit, refuse additional dispatch while preserving observation evidence through the recovery reserve or freeze UNAVAILABLE if even that fails. Evidence additionally has `raw:Blob|null`: raw bytes are mandatory when response validation requires them and otherwise null, with rawDigest still binding the canonical accepted observation. Import cannot turn a validation boolean or a digest without required source evidence into accepted authority. Audit pages and response chunks are part of complete portable recovery and semantic effect coverage.

`Effect={schema:1,id:ID,operation:ID,revision:U64,kind:EffectKind,artifact:ID|null,artifactPart:{kind:'tx'|'message'|'publication'|'query'|'projection',index:U32},bytesDigest:H,target:TransportTarget,dependencies:[{effect:ID,requires:'dispatch-recorded'|'accepted'|'confirmed'}],authorizationScope:H,state:EffectState,attempts:Attempt[<=64],evidence:Evidence[<=256],everDisclosed:boolean,conflict:boolean}`. EffectKind: `observation-query,spendable-preflight,tx-broadcast,relay-delivery,identity-publication,local-projection`. EffectState: `planned,blocked,in-flight,unknown,accepted,rejected,confirmed,reorged,conflicting,cancelled-before-disclosure`. Attempts/evidence above limits roll into authenticated immutable audit pages under operation quota, never discard uncertainty. `TransportTarget={adapterId:ID,adapterVersion:U32,destinationId:ID,canonicalTarget:Text(2048),policyDigest:H}`. No caller-selected proxy/URL; G3 applies.

`Attempt={id:ID,ordinal:U32,dispatchCommit:ID,artifactDigest:H,targetDigest:H,authRef:ID,boot:ID,state:'intent-durable'|'submitted'|'response'|'unknown',startedMonotonic:U64}`. `Evidence={id:ID,attempt:ID,source:'adapter-response'|'chain-observation'|'local-barrier',requestCorrelation:ID,result:'accepted'|'rejected'|'not-found'|'mempool'|'confirmed'|'conflict'|'reorg'|'timeout',txid:H|null,block:H|null,height:U32|null,adapter:ID,observationSequence:U64,rawDigest:H,validated:boolean}`. Validation recomputed from authenticated adapter protocol/correlation, not trusting imported `validated`. Local evidence preserves exact response bytes protected within bounds if protocol requires later verification. Wall timestamps may be displayed but never order authority.

| Input/event | Guard | Durable reducer outcome |
|---|---|---|
| schedule planned | Dependencies satisfied, exact artifact committed, selected authority and transport healthy | Commit attempt intent and effect=in-flight **before** any disclosure; only resolved barrier permits dispatch |
| crash between intent and send | Attempt intent durable, cannot prove no send | unknown, everDisclosed conservatively true; retain reservation |
| timeout/disconnect/malformed or absent correlated response | May have submitted | unknown, preserve bytes and evidence; never rebuild payment |
| accepted response | Correct operation/attempt/bytes/target correlation | accepted; relay acceptance is not recipient receipt nor chain confirmation |
| rejection response | Correlated valid response | rejected-at-this-target; if any submission possible keep recovery/reservations; another party may already hold bytes |
| mempool/confirmation | Canonical txid/bytes and validated configured chain evidence | accepted/confirmed; confirmation does not prove message delivery |
| not-found | Even after prior accepted/confirmed | add observation; no input release; retain prior strongest evidence and mark inconsistency if needed |
| reorg | Previously confirmed evidence no longer canonical | reorged; restore conservative reserved/uncertain membership, no replacement signing |
| late accepted after timeout/reject | Same immutable artifact; valid correlation | advance accepted evidence, never repeat signature/consume approval |
| late rejection after accepted | Same attempt or sibling | retain acceptance, record disagreement; conflicting if same authoritative source contradictory; do not downgrade to safe-to-retry |
| conflict spend / wrong bytes / cross-operation callback | Valid competing-spend evidence or inconsistent identities | conflicting; preserve all recovery; no automatic reservation release |
| cancel | Proven no signing/disclosure, no unknown commit | cancelled-before-disclosure; plan reservation can release atomically; after signing/uncertainty cancel delivery scheduling only |

Dependencies form acyclic ordered graph, sorted IDs, no self/unknown link. Query has no dependency on spendable bytes. For current Stamp route, spendable-preflight precedes explicit tx-broadcast and relay-delivery; a successful preflight may unlock exact-byte broadcast, not authorize new payment. Each transaction has its own effect; relay delivery requires selected preflight/broadcast states declared before approval. Declared dependency failure blocks downstream dispatch but never erases upstream exposure. An artifact-containing registry/forum request is spending-capable even if named metadata/vote/validation.

The current full-envelope validation request **is spendable-preflight**, not observation-query. It must meet final-artifact/consumed-approval/reservation/in-flight barriers. Alternative genuinely observation-only preflight may send only network ID, capabilities and public non-spendable query identifier, never signed tx/envelope/sufficient redeemable material; adding such a new route requires reviewed adapter mapping. No endpoint label changes the classification.

Aggregate `OperationState` reducer (ordered): any authority/effect mismatch -> conflicting; any canonical reorg -> reorg-observed; all effects cancelled with proven no exposure -> cancelled-before-disclosure; no consumed approval -> approval-required; no durable artifact -> prepared; any spend exposure plus required delivery rejected -> exposed-delivery-failed; any spend exposure plus required delivery unknown/blocked -> exposed-delivery-unknown; all required delivery/publication accepted and all tx effects accepted/confirmed -> delivered (explicitly not recipient-read or final settlement); any dispatch -> dispatching; otherwise artifact-persisted. A partial bundle is dispatching or exposed-delivery-unknown with per-tx evidence, never generic failed. Separate settlement flag requires configured chain verification and owner-selected retention; this proposal never automatically frees a disclosed outpoint on a rejection/not-found. Retain final artifacts, replay and spent-output recovery regardless of UI completion.

## C3 — Replay after eviction and restart

Volatile response cache256 is only an accelerator. Authenticated `Replay={schema:1,binding:RequestBinding,subject:ID,subjectKind:'operation'|'candidate'|'task',state:'prepared'|'completed'|'cancelled',resultDigest:H}` and operation originRequest persist in graph and backups. Accepted request lookup always consults durable index on cache miss. Same binding/same args returns original subject (or inspect-only recovery handle under new caller); same sessionEpoch/id with different args/method returns REPLAY_CONFLICT. Never deduplicate merely by recipient/amount: legitimate second equal payment has new request ID and fresh consent.

On reload/restart, live sessionEpoch revokes. Old IDs cannot be treated as new under old epoch. Recovery UI lists durable operations; requesting resume under a fresh epoch references an existing operation and C4, not prepare-send replay. Archived epochs retain index/tombstones through policy-selected logical profile lifetime; when quota reached, refuse new spending instead of evicting correlation. Historical IDs in imported records remain under origin profile/epoch; fresh profile remaps local lookup provenance but imports original durable request bindings to prevent implicit replay. Imported requests/approvals never execute. Duplicate root/import with overlapping operations merges by original binding plus artifact digest or returns conflict. Clock changes have no authority effect. If expired caller cannot authenticate lookup, return STALE and the scoped operation-list path; do not disclose foreign operations. No permanent secret bearer token is required for recovery.

## C4 — Fresh approval versus exact-artifact recovery

Three activities are distinct: **fresh signing** needs a live one-use approval and selected inputs; **observation** can only collect C2 evidence under configured transport/privacy policy; **delivery** transmits exact durable bytes and may enable spending even without new signing. No recovery operation has arbitrary signing authority.

Unselected policy: observe/inspect only, delivery returns POLICY_PENDING. Two complete proposed choices:

**R-A fresh consent:** restart/navigation/caller loss/activation revokes all grants. Each previously persisted final artifact remains inspectable. Main shows exact prior content/destination/transactions/cost and uncertainty in a fresh trusted ceremony. It creates a new one-use delivery grant bound to current caller/boot/epoch plus originating operation/generation and the immutable permitted effects/digests. TTL120s monotonic; grant cannot sign or add effects. Retained generation settlement explicitly names old operation; new active generation never supplies keys. Missing artifact means no continuation, only separately prepared fresh-signing workflow after resolving reservations. Destruction/retirement/conflict/revocation blocks minting.

**R-B preauthorized exact delivery:** only if owner selects it and original trusted ceremony separately accepts **the exact final-artifact/effect-set continuation policy**. Before first dispatch persist `Continuation={schema:1,id:ID,operation:ID,originGeneration:U32,artifactDigest:H,effects:ID[],targetsDigest:H,policyDigest:H,remainingAttempts:integer0..8,expiryUtcMs:U64,issuedClockFloor:U64,revoked:boolean,allowRetained:true,allowRestore:false}` within authenticated graph. It grants no signing, altered bytes, new target or new payment. Absolute maximum24h and8 dispatch attempts total, including unknown/lost attempts. On boot, main validates entire graph, nondeleting state, unresolved named operation, policy unchanged, exact artifact, reliable nondecreasing system time relative to persisted floor; backward time, unknown clock, forward past expiry, imported/copy-acquired profile or stale provider yields fresh consent required. Forward clock shortens, never extends. No full-store rollback defence is claimed. If trustworthy time cannot be established, R-B cannot continue unattended.

For each R-B retry, main mints an **ephemeral** recovery grant `{boot,currentInstallation,currentEpoch,originGeneration,operation,artifactDigest,effects,attempt,expiresMonotonic<=60s}` after atomically decrementing remainingAttempts and saving new clock floor with dispatch intent. Its caller is the registered main recovery service, not the historical renderer; it is never exposed through IPC. This explicit service identity exception applies only to preauthorized exact delivery, not ordinary effects. Process restart loses grant; persisted attempt remains unknown, another attempt consumes quota. Activation may retain this named delivery scope only when selected policy and original allowRetained both match; no inheritance to new operations. User revoke/cancel scheduling, policy change, destruction, unavailable provider, artifact conflict or expiry prevents minting. Restore never restores executable continuation. These constraints do not detect copied complete valid authority stores; OD freshness limitation and old-writer exclusion remain mandatory.

Non-payment identity policy choices are independent: I-A require trusted exact content/destination consent for every statement; I-B disable identity publication (typed POLICY_PENDING/UNSUPPORTED) until consent support selected. No open-ended ongoing publication or unattended spending capability is proposed. If owner wants an ongoing identity allowance, a new bounded design is required before enablement. Every signature purpose is isolated from raw transaction/message hash signing.

## C6 — Logical-origin records and current authorization

F4 preserves original Intent, Artifact, RequestBinding, approvals and nested references as authenticated origin records; T maps every current-purpose access to physical main authority without rewriting historical signed bytes. B7's registry applies to every nested Ref/ID. Artifact.commit is a historical persistence correlation, never proof of a barrier in the current installation. Current artifact materialization must pass B4's own commit/resolve before any allowed disclosure. On restore all continuations/approvals are nonexecutable evidence; A7 creates a new purpose-specific recovery task under the current installation. Fresh transactions use the current generation and native logical space; imported historical operations cannot supply fresh signing permission. Current final-artifact digest/txids/bytes remain immutable through reference mapping.

All64 lifetime attempts across an operation's effects and audit pages count toward F5's reserved credit, including failed/unknown attempts. Page rollover is representational bookkeeping: F6 projects a normalized effect history by ordinal, excluding duplicate container/page references and page packing while retaining each original attempt/evidence exactly once. Effect-audit-page records remain authenticated/present in the portable set; semantic pair treatment is specified F6. Genuine added evidence changes coverage. No quota permits forgetting prior exposure. Live delivery grants created by recovery-delivery consume only one exact approved effect dispatch; a batch requires explicitly listed effects and separately counted one-use dispatch tickets committed before their individual disclosure, never implied additional attempts.

Content in original Intent, Artifact, scalar recovery and response evidence is retained even after ordinary history deletion. D3's display promise and trusted deletion Summary must say so. Existing REG-01 automatic402 containment, REG-02 received-output verification and REG-03 diagnostic redaction are unchanged requirements. Every main route must retain those properties; documentation does not implement the boundary.
