# Annex F — Concrete protection and portable-container proposal

Version `5.0.0-draft`. **Unselected integration proposal; no adoption or implementation authorization.** Existing cryptographic library constructions are used as proposed building blocks; no replacement cipher, KDF or ratchet is specified. Independent Cryptography and external human integration review are prerequisites to adopting this format/key hierarchy, sensitive reliance and recovery-dependent retirement. [B](B_LIFECYCLE_REVISIONS_AND_COMMITS.md), [C](C_OPERATION_AND_EFFECT_TABLES.md), [D](D_MIGRATION_AND_DESTRUCTION_RESTART_TABLES.md) and [E](E_DESCRIPTORS_AND_COMPATIBILITY.md) supply semantic schemas.

## F1 — Canonical records and key hierarchy

Proposed canonical encoding `C(x)` is RFC8949 core deterministic CBOR (§4.2.1): shortest definite lengths/integers, map keys sorted by bytewise lexicographic order of their deterministic encodings, never the alternate length-first convention. No tags, floats, undefined, indefinite lengths, duplicate keys, unknown fields or noncanonical equivalents. Map keys are exact ASCII field names from the closed schemas; enums are exact text; text valid UTF-8 with no implicit normalization. Arrays preserve declared semantic order; sets explicitly sort as below. Internal U64/Sat/revisions are CBOR unsigned integers, not decimal text; IPC decimal strings are range-checked then converted losslessly. IDs decode to16-byte bstr, H to32-byte bstr, cryptographic keys/scripts/data are bstr, booleans/null as declared. Every optional map field is **absent** when not present, not encoded null unless schema explicitly permits null. Code/schema notation has no effect on these wire types. Decoder re-encoding equality is checked within bounded resources before accepting canonical input. [RFC8949](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2.1).

`RecordPlain=[1,type:tstr,id:bstr16,revision:uint,context,body]`; `context=[profile:bstr16,wallet:bstr16,generation:uint,network:tstr,purpose:tstr]`. Profile-wide records use generation0xffffffff and wallet=manifest wallet ID; actual generation allocation excludes0xffffffff. Lifecycle context is `[installation:bstr16,slotEpoch:uint,'installation-lifecycle']`, with separate record class/key. Body must match the B7 closed logical-type registry and referenced B/C/D/E/F schema. RecordPlain remains the logical origin envelope; actual main-owned storage uses F4 CellPlain plus authenticated Binding. Native and restored profiles use the same separation. Profile-wide records cannot be used as per-output key records. Purpose equals registered type purpose, not a caller string.

`D(label,x)=SHA256(C([label:tstr,x]))`; labels literal `finney.rc03.record.v1`, `finney.rc03.members.v1`, `finney.rc03.intent.v1`, `finney.rc03.output-binding.v1`, `finney.rc03.coverage.v1`, `finney.rc03.artifact.v1`, `finney.rc03.scope.v1`. Record Ref digest is D(record,RecordPlain), **not local ciphertext digest**. Membership page is `{schema:1,page:ID,entries:[[type,id,revision,recordDigest]...]}` sorted by raw UTF-8 type bytes then raw ID bytes, unique `(type,id)`, <=1024 entries and256KiB; pages are sorted by first membership key, disjoint and complete. Manifest references page plaintext digests. Membership excludes the manifest itself and membership-page nodes, which are anchored by head and manifest respectively, preventing recursive self-hashing. Duplicate/missing/extra committed membership fails. References plus object lookup keys use expected profile/type/id/revision, never an arbitrary storage path. Intent digest is D(intent,exact Intent); aliases sort by network/txid bytes/vout numeric; effect dependency sets by raw ID; original input/output/encounter/transaction order never sorted away. Type-purpose mapping is exact: root -> legacy-wallet-root, scalar -> output-recovery, every other profile RecordType -> its identical type token. A BoundKeyRef spending/identity purpose is additionally checked against that record's allowed use; it never rewrites the stored purpose. Root/output/scalar context generation is its actual generation; profile-wide catalogue/manifest/policy/membership pages use the reserved profile-wide value; all other records carry their owning generation or the explicit profile-wide value according to the declared body scope.

Proposed Windows chain of protection:

1. Generate independent random32-byte `KL` per installation and `KP` per profile using OS-backed CSPRNG. DPAPI/current-user via pinned Electron safeStorage wraps **separate** canonical anchors encoded as base64 text: `[2,'life',installationId,bootstrapIntentDigest,KL]` and `[2,'profile',installationId,profileId,profileInitIntentDigest,keyId,KP]`. Validate embedded context against selected installation slot after unwrap; exact bytes/length only. Wrong-account/unavailable/corrupt refuses. No plaintext fallback. Anchors held in distinct lifecycle/profile storage domains. Protected expected installation/slot comes from authenticated lifecycle head, not a replaceable record's self-description. Initial installation identity depends on controlled package mapping and successful absence probe; same-user host compromise and complete self-consistent rollback remain outside claims.
2. Standard HKDF-SHA256 (RFC5869), IKM=KP, salt=profileId16, info=ASCII `finney.rc03.profile.record-aead.v1`, output32 gives `Krecord`. Separate info `finney.rc03.profile.head-mac.v1` gives `Khead`; `finney.rc03.profile.journal-mac.v1` gives `Kjournal`. KL with salt=installationId and info `finney.rc03.life.head-mac.v1` / `finney.rc03.life.record-mac.v1` derives lifecycle keys. No wallet/identity scalar or mnemonic is a storage/backup key. Standard Node crypto HKDF/HMAC/AES-GCM in pinned packaged runtime is the proposal; runtime/OpenSSL versions must be recorded. [RFC5869](https://www.rfc-editor.org/rfc/rfc5869.html).
3. Actual storage envelopes are [2,context,type,id,revision,nonce:bstr12,ciphertext:bstr,tag:bstr16], type exactly cell, binding, binding-page, physical-members, authority-page or physical-manifest. Plaintext is C([2,type,id,revision,context,body]); body matches that exact physical schema below/B7. D(label,whole plaintext) uses finney.rc03.cell.v2 for cell, finney.rc03.binding.v2 for binding, finney.rc03.binding-page.v2 for binding-page, finney.rc03.physical-members.v2 for physical-members, finney.rc03.authority-page.v2 for authority-page and finney.rc03.physical-manifest.v2 for physical-manifest. Purpose equals physical type; non-cell physical records use profile-wide generation. AAD is exactly C(['finney.rc03.record-aead.v2',2,context,type,id,revision]). AES-256-GCM Krecord and16-byte tag remain unchanged. F8 authenticates and consumes a fresh random96-bit nonce permission BEFORE every encryption attempt, including aborted/uncommitted staging; maximum2^24 reservations per profile key, no reset/rekey fallback. Exact-envelope reuse is not another encryption. Context and committed physical Ref digest must match after decryption. Logical RecordPlain hashes remain version1 and never masquerade as physical-cell hashes. This explicit schema/AAD version revision needs new independent vectors and external integration review; no primitive or wallet-wire derivation changes.
4. Authenticated head [2,installationId,profileId,revision,physicalManifestId,physicalManifestDigest,commitId,mac] uses HMAC-SHA256(Khead,C(preceding fields)). PhysicalManifest names the BindingRef, exact physical members and logical authority snapshot; Binding anchors each original envelope through its expected CellRef. B4 journals use HMAC-SHA256(Kjournal,C(['finney.rc03.commit.v2',Commit])). Membership never relies on replaceable self-authentication. A prepared journal cannot promote stages absent the atomic committed head/result. Original logical membership pages remain source evidence; physical member closure is checked independently.
5. L records use `[1,installationId,slotEpoch,type,id,revision,body,mac]`, HMAC with lifecycle-record key over preceding fields; L head separately authenticated with lifecycle-head key. Only nonsecret D4 metadata lives there, no KP. Atomic sync L head/member update anchors expected lifecycle revisions. Deleting KP/P cannot erase KL/L. Whole L+anchor valid rollback remains a stated limit. Installation identity or anchor substitution from another installation conflicts; loss never generates a replacement key over residue.

Local encryption keys/DPAPI blobs and nonce accounting are never portable. F4 defines the complete original logical envelope and total physical binding; every original reference validates before binding. F6 defines exact semantic coverage. F8 supplies pre-use nonce permission for every physical-cell encryption. No imported approval/continuation is executable.

## F3 — Pending credential and privacy alternatives

Both credential alternatives share encoding1: valid UTF-8 bytes of entered Unicode string **without normalization, case folding, trimming or newline conversion**; reject NUL/unpaired surrogates; preserve all permitted whitespace and compare confirmation byte-for-byte. BIP39 normalization is unrelated. Import min1/max1024 bytes to recover supported historical P4 artifacts; export policy stricter below. Trusted channel only, no logging/string-copy erasure guarantee.

Credential G: main generates32 random bytes, displays64 lowercase hex characters in trusted UI, password bytes are those64 ASCII characters; confirmation before export, independent of mnemonic. Credential H: user-entered passphrase16..1024 UTF-8 bytes, twice confirmed with visible whitespace/encoding notice and offline-guessing warning; no claim length guarantees entropy. Either uses same exact KDF; weak human input never causes lower costs. Owner must choose G or H, storage/transfer guidance and recovery-device envelope. Generated secret itself is never in clear header or clipboard by default.

Privacy alternative P-min uses the exact F2 header with flags0 and raw Portable bytes. It leaks format/suite/KDF/byte length and equality of identical copied files, but no deliberate stable clear identity. P-pad flags1 uses the same cipher suite and encrypted closed wrapper {schema:1,data:bstr,pad:bstr}; data is exactly C(Portable), pad is OS-random bytes. No normalization, compression or plaintext identifier is added. Both policies remain pending; parser accepts only explicitly selected/allowlisted flags, never silently falls back to flags0 after padding failure.

Exact padding rule: h(n) is the deterministic CBOR byte-string length-header size:1 for0..23,2 for24..255,3 for256..65535,5 for65536..4294967295,9 beyond. L(d,p)=18+h(d)+d+h(p)+p. The constant18 is the map header, encoded keys data/pad/schema and schema value1. Let B=1048576. Starting k=ceil(L(d,0)/B), examine k up to128 in ascending order. For each h band solve p=kB-18-h(d)-d-h, accepting only nonnegative integer p in that band's interval. Choose the first feasible k and its unique p. An unreachable nearest bucket is SKIPPED; later feasible bucket is not 'nonminimal'. If none exists by128MiB, return PADDING_CAP with zero publication/activation, preserving source. Decoder independently recomputes this exact minimal feasible pair after authenticated canonical parsing, rejects any other bucket/pad length, and charges wrapper/data/pad resources before allocating. Length alone is not authority to allocate. PayloadSchema2 and inner format5 are checked before qualification.

Proposed arithmetic fixtures, not independently verified encoding vectors: d1048529/p23 ->1048576; d1048527/p24 ->1048576; d1048296/p255 ->1048576; d1048294/p256 ->1048576; d983015/p65535 ->1048576; d983012/p65536 ->1048576. Gap d1048528 has totals1048575 at p23 and1048577 at p24; choose next bucket2097152,p1048596. Likewise d1048295 and d983013/983014 skip the unreachable first bucket. d134217680 cannot reach the128MiB bucket and the next is beyond cap: PADDING_CAP. R96 limits legitimate source payloads so its largest required bucket is97MiB. Exact encoded bytes/digests remain UNVERIFIED until independent implementations test them; this assignment checks only the stated integer arithmetic, not a CBOR/crypto harness.

P-pad conceals fine size only, leaks the chosen1MiB bucket and format, and may jump an additional bucket at a header-width gap. File names/OS metadata and identical-copy equality remain visible. Credentials and padding are owner choices; changing a credential cannot revoke old artifacts or copied signing keys.

## F4 — Lossless logical graph and total local binding

This version proposes payloadSchema2 and container format5; it is incompatible with the unimplemented format4 draft. Suite/KDF1 and the cryptographic primitives are unchanged. There is no format4 fallback. The following representation replaces body-only dedicated collections. Every record, including an unreferenced Replay or Reservation, carries its complete original envelope exactly once. No decoder infers envelope metadata from incoming references.

Closed types (all integer/byte types use F1 canonical encoding):

~~~text
OriginSpace={schema:1,id:ID,profile:ID,wallet:ID,network:Network}
QRef={space:ID,ref:[type:RecordType,id:ID,revision:U64,digest:H]}
PortableRecord={space:ID,original:RecordPlain}
PortableAuthority={schema:1,epoch:U64,policy:QRef,
 generations:[{space:ID,generation:U32,role:Role}],
 current:QRef[],historical:QRef[]}
Role=0(candidate)|1(active)|2(retained)|3(retired-local-kept)
Portable={format:5,suite:1,payloadSchema:2,credentialEncoding:1,
 spaces:OriginSpace[],authority:PortableAuthority,records:PortableRecord[],
 coverage:{schema:2,bytes:bytes,digest:H},complete:boolean}
~~~

At most16 spaces/generations combined,65536 records (including historical versions and supporting pages), and the F5 charged-byte cap. Arrays spaces/generations are sorted by space bytes then generation; records by (space,type UTF8,id bytes,revision numeric). No duplicate qualified envelope key, even with equal bytes. Current contains one version per (space,type,id); historical contains all additional versions needed by any retained Ref, and no duplicate current member. Both reference arrays sort by the same key. Unknown types/versions/context/fields reject. A RecordPlain's source profile/wallet/network must equal its OriginSpace; its logical generation/purpose must match its body and the type registry. Current and historical membership enumerates every exported record exactly once, including records with no incoming references. Closed-reference traversal may not silently omit an unreferenced replay/observation/tombstone. Original local membership pages and their raw digests are included if referenced, as are complete raw-source/audit/artifact chunks. Operating-system anchors, encryption keys, nonces, usage ledgers and live grant secrets are not RecordPlain and are never portable.

Every original Ref is first resolved in the containing record's OriginSpace; explicitly qualified QRefs use their stated space. Exact type/id/revision/context and D(record,original) must match. ID-only edges are not guessed Refs: their target type and current/historical interpretation are specified in B7. A missing, duplicate, ambiguous or substituted target rejects completeness and leaves the source intact. Digest Ref edges must form a finite DAG; cycles through IDs are permitted only for the declared operation/effect and output/scalar relationships, with no recursive digest dependency. All original envelopes are validated before constructing local bindings. An authenticated file authenticates these supplied original bytes; it does not prove their past on-chain existence or possession of the originating OS key.

Local restoration uses explicit indirection instead of rewriting immutable intent/artifact bytes. Physical profile/wallet IDs and keys are fresh; logical source IDs and original request/intent provenance remain unchanged. The exact local representation is:

~~~text
CellPlain=[2,'cell',localId:ID,localRevision:U64,localContext,
 {space:ID,original:RecordPlain,originalDigest:H}]
CellRef=['cell',localId:ID,localRevision:U64,cellDigest:H]
Binding={schema:2,profile:ID,wallet:ID,incarnation:ID,prefix:bytes12,
 spaces:OriginSpace[],pages:PhysicalRef[],nextOrdinal:U32,
 generations:[{space:ID,logical:U32,local:U32,role:Role}],
 authorityEpoch:U64,active:U32|null}
~~~

localContext uses F1's profile/wallet/mapped-generation/network/purpose='cell'. CellDigest=D('finney.rc03.cell.v2',CellPlain). The outer AES-GCM record encoding, AAD and expected head are version2 and bind that exact physical context; key derivation labels, nonce size, tag size and algorithm remain as F1. A native new profile uses the same logical-record/cell separation, so subsequent restore does not nest a previous CellPlain or recursively copy old physical bindings. Logical envelope revisions survive export and import; physical localRevision initially1. Physical encryption counters are fresh only because KP is genuinely new in a separately admitted destination, never by resetting an old profile. Original graph bytes cannot be passed directly to the signer as local authority.

Deterministic binding algorithm, given the once-persisted candidate identity/prefix: (1) validate the entire original graph; (2) sort original qualified keys as above; (3) for ordinal i starting1, assign localId=prefix12||uint32be(i); verify prefix uniqueness in the selected destination; (4) sort logical (space,generation) pairs and assign local generations0..15; profile-wide0xffffffff stays reserved; (5) compute each CellPlain/CellRef independently of the binding table; (6) build the bijective from/to table and generation table, authenticate them from the new head; (7) expose only the inactive candidate. Restart uses the same committed prefix/IDs; unknown preparation never allocates a second mapping. Imported same-body records at different revisions remain separate validated entries, not collapsed by their body. Repeated imports of overlapping roots/outpoints use the existing ownership-conflict/alias checks, not parallel signing authority.

Total reference transformation T is a main-internal typed view: every logical Ref/QRef becomes its exact CellRef through Binding; every logical profile/wallet/generation field in a current-purpose request/view becomes the corresponding physical binding; ID relationships resolve the B7 declared logical target then T. Cryptographic scripts, txids, scalar bytes, derivation paths/encounter ordinals, original RequestBinding, exact Intent/Artifact bytes and historical provenance are immutable origin data, not locally rewritten signatures or approvals. The view carries both OriginKey and current BoundKeyRef; a purpose-specific main operation must validate the local binding, origin envelope, current generation role, caller and fresh authorization. No ambiguous untyped string is treated as a reference. A new mutation serializes a new logical envelope through the inverse declared mapping; original immutable intent/artifact/history is never rewritten. Its new Cell and Binding update share B4's atomic commit. No generic original-record access or raw-key IPC is introduced.

Approval/continuation/task/external states in original records are historical evidence after restore. membership in Binding.imported plus a new installation/boot/epoch means no imported consume ID, grant, task or continuation is executable. Recovery imports classify every operation through C's uncertainty reducer, retain reservations/replay, and require A's explicit current recovery ceremony before exact-byte delivery. No shell launch or deletion resumes from imported tasks. Local admission state is candidate until explicitly activated; PortableAuthority's role is snapshot evidence, not permission to activate. Every nested reference has the same validated transformation, including supporting pages and unreferenced current records. Complete fresh-profile reconstruction uses only this package, its credential and the new provider: no original OS keys, physical cell files or relay history.

Binding pages are {schema:2,id:ID,ordinal:U32,entries:[{from:QRef,to:CellRef,imported:boolean}]} with <=1024 entries and <=256KiB each. Binding.pages contains <=65 sorted contiguous-ordinal PhysicalRefs and no missing/duplicate from/to key. The imported flag is stored only in the corresponding page entry. References to Binding.imported denote that authenticated flag view, not an extra root field. Binding root <=64KiB. Physical member pages are {schema:2,id:ID,ordinal:U32,entries:PhysicalRef[<=1024]}, <=256KiB; each member appears once. PhysicalManifest references <=128 pages, excluding itself and those page nodes from entries to avoid self-hashing. All pages are directly authenticated by the manifest's refs; Binding and every cell/page are accounted once. Authority index is also paged: AuthorityIndex={schema:2,epoch:U64,policy:QRef,generations:[{space:ID,generation:U32,role:Role}],currentPages:PhysicalRef[<=64],historicalPages:PhysicalRef[<=64]}. AuthorityPage={schema:2,id:ID,ordinal:U32,kind:'current'|'historical',entries:QRef[<=1024]}, <=256KiB, type/purpose authority-page. Current/historical together enumerate <=65536 original envelopes once. PhysicalManifest.logicalAuthority is this bounded AuthorityIndex; flattening its authenticated contiguous sorted pages yields exactly PortableAuthority. Pages themselves are included in physical member accounting. No monolithic1MiB mapping/authority array is required. Each initial binding entry's flag is true on import, false on native creation. Later native records are false; original imported approvals remain inert even after legitimate new operations. New local ordinals append from nextOrdinal under the same atomic head and increment without reuse; overflow blocks, never renumbers live references. New logical origin space uses the destination's original profile/wallet IDs; adding one must fit sixteen-space capacity. Existing original IDs are never silently aliased into it.

The binding table is also the unique ownership catalogue for interpretation of source-scoped contexts. A supplied source namespace is never permission to choose another live profile. Adoption of this cell/binding integration is a design proposal requiring the designated reviews and external human assessment; document validation does not validate its implementation.

## F5 — Compositional recovery and parser budget

Supported-capacity proposal R96 (OD-02G) or explicitly unavailable larger-capacity design; neither is owner-selected. This replaces the incompatible independent64/128/256MiB admission promises. Protocol ceiling remains128MiB plaintext,2049frames and134260821 file bytes; the supported application's complete Portable representation must fit a stricter charged96MiB envelope before it admits obligations. An otherwise authentic larger artifact returns CAPACITY_UNSUPPORTED, preserves source and cannot be called complete locally. Larger support needs a versioned budget/device proposal, not silent truncation.

Charge is exact canonical Portable length with every mutable unsigned integer conservatively charged9 bytes, each supported role/state at its maximum declared encoded width, plus reserved future-obligation bytes. Include original envelope wrappers, all original/historical graph/source/audit/provenance records, spaces, authority, coverage bytes/digests, complete raw artifacts, tasks and tombstones. Duplicate physical/semantic caches are not portable but their local cost is separately bounded. No compression, omitted historical material or raw Ref guessed from another record reduces the charge. Count ceilings are65536 logical records and sixteen logical generations/spaces, subordinate to96MiB. Current charged bytes + irrevocably reserved future credits <=100663296 at every admitting commit.

For canonical raw payload length d<=96MiB, P-min plaintext=d; P-pad uses F3, whose largest possible supported result is97MiB. Thus maximum supported ciphertext file is64+101711872+1553*21=101744549 bytes. The format's128MiB ceiling remains a rejection bound for externally supplied input, not permission for Finney to accumulate unrecoverable local obligations. The 2200*65536=144179200-byte example fails admission before creating that state, even without wrappers. It is never fixed by filtering the eventual backup.

Physical materialization budget: original Portable<=96MiB plus <=1024 extra encoded bytes per logical record for cell/context/local map/membership and <=8MiB fixed head/catalogue/indices is at most168MiB for65536 records. Candidate hard logical cap192MiB therefore leaves24MiB margin; exceeding the exact1024-byte overhead contract rejects before admission and requires design revision, not an allocation exception. Cell wrappers have bounded IDs/context and contain each original envelope once; bindings contain no duplicate original bodies. Native/stage exact bytes are measured against this bound. Import can retain one encrypted input<=101744549, two192MiB candidate/stage copies, and16MiB I/O reserve: total<=521174949 bytes, below512MiB=536870912. No third full copy or plaintext temporary file is permitted. Export needs one frozen pin and one ciphertext temp plus final publication through same-volume rename; it cannot double-copy unnoticed. Native DB/WAL/compaction filesystem amplification is a separate measured physical-space prerequisite, with a proposed2GiB reserved workspace and1GiB authority quota; failing actual backend reservations yields UNAVAILABLE without claiming durability or deleting source. The512MiB figure bounds accounted logical staging, not arbitrary storage-engine amplification.

The96MiB charge includes8MiB emergency captured-evidence reserve. New owner-originated obligations stop at88MiB inclusive of all held credits. At most eight incoming reads are armed; each reserves1MiB raw frame plus bounded conversion/evidence credit before read, and count/byte/nonce/staging credits must all fit. No unbounded socket buffers. A new outgoing operation reserves its exact final artifact upper bound (<=8MiB) plus4MiB future-effect credit and64 total attempts; retained data across all effects may not exceed this credit. New dispatch stops before its reserved evidence capacity is exhausted. Unexpected allowed input is encrypted into a bounded observation/quarantine record, classified capacity-incomplete and pauses new admission; it is included in backup, never silently dropped or counted complete. Before reserving the next read, ensure remaining evidence/nonce space; if none, stop reading/acknowledging and report incomplete capacity. Unlimited future network evidence and unsolicited post-close delivery are not promised. Exact duplicates may reuse existing byte-identical evidence, but no distinct uncertainty may be evicted. If storage/nonce exhaustion prevents persisting already read bytes, hold only the bounded pending buffer, emit failure without acceptance acknowledgement and freeze; do not claim that receipt durable or recovery complete. Original acquisition images/artifacts stay untouched when they exceed these limits.

Import/export concurrency one active/one queued per installation. Header preflight exact64bytes; protocol counts/lengths/KDF tuple checked before expensive work. KDF64MiB, isolated worker cap256MiB, decoded live-object cap64MiB, installation-accounted working-memory cap384MiB including clones and buffers; incremental parsing avoids materializing all records in RAM. Decoder depth16 for individual records, maximum2,000,000 nodes, fields<=64 per map, text<=65536 (raw record<=1MiB), same schema count caps. Coverage DAG computation uses disk-backed memo records bounded within candidate staging; no repeated exponential recursion. Encrypted stream pre-FINAL data is provisional; no projection or activation. Fixed KDF costs never decrease on slow hardware. Proposed device deadlines KDF10s, active work120s, bounded I/O30s and cancel<=2s remain unmeasured acceptance requirements. Selected provider/backend can refuse insufficient resources; source and old authority remain intact.

## F6 — Exact recursive coverage and qualification

Source-integrity references and semantic coverage references are distinct. Proposed projection version2 includes the following explicit orchestration exemptions, including their task-subject replay records; it never blanket-exempts all replay or retirement changes. Validation always resolves every original Ref against the authenticated logical graph first. Physical Cell metadata, Binding.prefix/cell IDs/local revisions, ciphertext/nonces and source record revisions never enter semantic coverage. A changed original body cannot be hidden by changing Binding. Coverage version2 is deliberately separate from record-digest version1 and physical-cell version2.

Define K(r)=[spaceId,type,logicalId]. Define P(r) by the closed projection table below. At every Ref/QRef leaf in an included field, recursively substitute ['ref',K(target),S(target)] where S(r)=D('finney.rc03.semantic-record.v2',[K(r),P(r)]). Source profile/wallet/network/generation/purpose remain in P's context, with logical generation; outer record revision is excluded. For ID-only edges, substitute ['id',spaceId,targetType,logicalId] after B7 target validation; the referenced record independently participates in the covered record set. No raw Ref digest or revision survives inside projected aliases, inventory, input snapshots, provenance or pages. All other included values use their exact canonical F1 encoding; ordered transaction/input/output/encounter arrays retain order; only declared sets sort by canonical bytes. Reject a digest-reference cycle, missing type rule or unresolved reference before computing coverage. Do not truncate recursion or replace a cycle with a magic hash.

For each eligible current/historical record form [K(r),S(r)]. Sort by space,type UTF8,id,S bytes; deduplicate only identical pairs caused by semantically identical historical versions. Distinct semantics for the same ID remain separate. Add a sorted current-root selector [K(r),S(r)] for each current semantic root, so switching current membership to different historical semantics is visible. Every non-bookkeeping record in the portable set is eligible; supporting records are included as well as being recursively referenced. No record is omitted because it is not in the spendable cache.

CoverageBytes=C([2,'finney.rc03.coverage.v2',sorted OriginSpace tuples,
 [authority.epoch,sorted authority.generations,projected policy QRef],
 sorted current-root selectors,sorted unique eligible pairs]).
CoverageDigest=SHA256(CoverageBytes). This exact byte string is carried in Portable.coverage and independently recomputed, not trusted as a supplied digest. Complete is recomputed from validation/quarantine/capacity/descriptor checks. Physical installation/profile IDs are excluded; logical identities and current lifecycle/epoch are included. Actual local role changes after import/activation legitimately change subsequent coverage; original-file verification uses its original authority snapshot before any new activation.

Nested projection definitions: Intent projects every declared field except schema, replacing all input/change Refs recursively. policyDigest remains a commitment to the exact selected policy semantics, which contain no Ref or mutable record revision. RequestBinding and its argsDigest/callerDigest remain immutable origin provenance, not a current caller grant. Artifact projects id, transactions/messages/publications (including Blob length, raw digest and recursively projected chunks); replace intentHash with projected Intent and omit commit (barrier correlation only). Artifact.digest is the commitment to ordered exact raw transactions/messages/publications and their IDs, not storage refs; C1's digest domain encodes those raw byte sequences, lengths and ordered IDs. If a source digest was computed otherwise it must be preserved as origin evidence and cannot pass this schema. Effect.authorizationScope projects [operation origin key, projected Intent, Effect.kind, projected target, bytesDigest]; targetDigest is raw canonical target/adapter policy, never a storage Ref digest. Scalar.bindingDigest projects E1's binding tuple recursively including aliases.evidence. Original SourceIdentity.recordDigest/inventoryDigest and Provenance hashes are immutable original raw-byte facts, not live Ref digests; they remain unchanged on local record revisions. Qualification/Artifact.commit and Attempt.dispatchCommit have no semantic effect after barrier validation. Blob.digest hashes exact concatenated bytes, unchanged by storage revision; its chunks recursively project body bytes and original artifact/ordinal identity. scopeRefs and nested pages use the same Ref rule unless their entire closed bookkeeping record is explicitly excluded. Excluded records may reference included records but cannot be the sole membership authority for them. Cross-type unknown hashes/fields reject instead of receiving a generic exclusion.

Here 'all except schema' means every declared field in the B7 registry, not arbitrary unknown extensions; a future field/type needs a new reviewed projection version. The projected scalar binding and operation intent are expanded using this same recursive rule, preserving original logical IDs/context and fixed key encoding. No independent caller-supplied alternate projection is accepted. Immutable artifact/tx/message byte digests remain raw byte digests. Role/epoch changes, new raw evidence, reservations, replay outcomes, remainingAttempts/expiry/revocation, current-root changes and relevant policies stale coverage. No-op reencryption, record-revision changes and qualification bookkeeping do not. Tests must cover every inclusion/exclusion, not merely assert a digest changed.

SnapshotToken (B7) pins original immutable graph and Binding at an exact head. Export can release writer while the pin persists; it cannot change snapshot membership as new records arrive. Qualification is B7's backup record, excluded above. Verify actual finalized artifact authentication, canonicality, complete graph, original digests, transformed bindings and all required known scripts against the pinned CoverageBytes; operational qualification never signs a live transaction. Acceptance additionally needs fresh-profile offline synthetic recovery evidence. Recording a qualification cannot stale it. A real subsequent semantic mutation does.

Retirement follows D2: prepare/approve/fence records are orchestration only, with no generation/epoch mutation before final comparison. Under a drained fence, compare one qualified artifact to current coverage, then atomically change the generation to retired-local-kept and increment epoch. That successful post-transition mutation stales the old artifact for a *later* retirement/destruction but does not retroactively invalidate the just-authorized transition. No repeated-export loop is required for the first valid transition. Local key removal remains explicitly unavailable pending its separate graph design and owner choice. Destruction instead binds the final frozen pre-deletion coverage and actual file evidence into L under D4.

Qualification availability means current exact bytes on stable separately retained media/domain or mounted user-held media with explicit custody acknowledgement. Stable OS file identity, nonwritable read handle/selected storage exclusion and current content authentication are required, not a stale path/digest. If exclusion cannot be proved, the destructive transition is unavailable. Whole valid-store rollback, future unknown outputs and future media survival remain outside claims.

## F8 — Authenticated pre-use nonce accounting

AES-GCM uses the same random96-bit nonce construction and2^24 lifetime upper bound; this is a proposed accounting mechanism, not a new nonce generator or rekey policy. One main encryption service owns Krecord for a profile; workers receive no reusable key or nonce ticket. KP has immutable keyId=profile anchor's main-generated ID, bound by L. Profile usage occupies a separate namespace U in the SAME native DB as P, outside graph-head rollback/GC. U is authenticated with Kjournal and domain labels below; it is plaintext nonsecret metadata (nonces/counts/purpose hashes), never recursively AES-encrypted.

~~~text
UseEntry={schema:1,sequence:U64,nonce:bytes12,attempt:ID,
 targetDigest:H,plaintextDigest:H,purpose:'cell'|'binding'|'binding-page'|'physical-members'|'authority-page'|'physical-manifest'}
UsageHead={schema:1,keyId:ID,profile:ID,used:U64,root:UsageRef,
 revision:U64,cap:16777216,mac:H}
UsageRef={id:ID,digest:H,count:U64,min:bytes12,max:bytes12}
UsageNode=leaf{schema:1,id:ID,entries:UseEntry[<=128]}
 | branch{schema:1,id:ID,children:UsageRef[<=128]}
~~~

Entries and child ranges sort by nonce bytes, unique disjoint ranges. Tree height<=5, count sums exact, nonempty children; empty initial root is an explicit leaf with count0 and min=max all-zero12 sentinel, never a usable nonce. Digest=D('finney.rc03.usage-node.v1',node); authenticated UsageHead MAC is HMAC-SHA256(Kjournal,C(['finney.rc03.usage-head.v1',head fields excluding mac])). The expected root prevents an attacker replacing a leaf and its digest. U root update is one atomic sync batch with all full immutable changed nodes; no plaintextDigest is accepted from renderer. Missing root/path/leaf or inconsistent count is CORRUPT, not an empty ledger. Sequence uniqueness and used count are checked on insert; the authenticated tree prevents nonce duplicate reuse. Head revision/cap/key binding cannot be chosen by caller.

Initialization occurs once after a new KP anchor is durably tied to L's profile-init intent and before any encryption. An absent usage head is initializable only if that exact L intent certifies a never-used key and P has no envelope/stage/reservation; otherwise missing U freezes. Legacy migration acquires a genuinely new destination KP; no existing key is regenerated over residue. Source key usage is never imported to authorize a new profile, and copied protected stores are unsupported acquisition.

| Edge | Required durable/action outcome |
|---|---|
| request | Single writer validates payload/purpose/target, graph and resource credits; computes complete plaintext/target hashes; refuses cap/disk/unknown U before requesting encryption |
| draw | OS RNG produces12bytes; existing nonce means burn no encryption, retry at most16 draws, then RNG_UNAVAILABLE; never reuse the duplicate |
| reserve | Before AES invocation, atomic sync U batch inserts new entry and increments used/sequence/head. Successful authenticated resolution is pre-use permission, not a success marker written afterward |
| reserve ACK lost | Do not encrypt with that ticket even if later found committed. Resolve U conservatively; committed entry remains permanently spent. Unknown freezes further key use |
| AES attempted | One in-memory invocation only for its persisted ticket and exact plaintext/target; success, error or worker/process crash all consume it forever |
| envelope stage/head failed | Preserve U consumption independent of rollback to H0; retry needs a new nonce/reservation, even when no ciphertext became reachable |
| restart | Discard every prior boot's ticket; authenticate current U head and accessed tree paths before any new permission. Orphan ciphertext/aborted stage never reduces used. Ordinary crash cannot reset U to the graph's older usage |
| GC | Old tree versions may be reclaimed only after resolved head and retained reader pins; current tree's complete nonce set and used remain. Deleted wallet records do not remove their UseEntries |
| exhaustion | KEY_USAGE_EXHAUSTED, no new encryption/sign/effect/admission needing persistence; existing authenticated decryption/inspection allowed. Complete read-only backup remains available through a nonsecret L-owned Task with fresh trusted backup consent and an immutable authenticated P pin, without P writes or Krecord encryption. Its encrypted portable stream uses its independently selected credential/suite, not a rekey/fallback for P. No qualification is written to P; L stores only artifact/coverage metadata. Artifact verification and export may not mutate old authority No automatic key replacement; rekey requires separately reviewed authorization |

Permission is never returned over IPC and a retry cannot replay an old attempt ID. Concurrent candidates/import/envelope writes share this service and ledger; source/storage graph locks do not create independent nonce allocators. Budget key uses before arming network reads or approved disclosure. Keep a4096-use emergency headroom and corresponding disk reserve for bounded already-accepted recovery; stop new obligations when used plus held worst-case credits would consume that headroom. At absolute exhaustion no guarantee of persisting new incoming bytes exists: F5 refusal/no-ack rules apply, without false durable receipt claims. Ledger disk quota can stop writes before the cryptographic count cap;2^24 is not a promise to fit that many entries on every device. Full valid P/U/KP/L rollback or same-user hostile host is outside freshness claims, separately from the ordinary-crash ordering above. External human review must assess this exact lifecycle, domains, random-nonce residual risk and aggregate GCM bounds.
