# Annex D — Acquisition, cleanup, deletion and surviving lifecycle evidence

Version `5.0.0-draft`; proposed only. [B](B_LIFECYCLE_REVISIONS_AND_COMMITS.md), [F](F_PROPOSED_CRYPTOGRAPHIC_FORMAT_AND_COMMITMENTS.md) and [G](G_DEPLOYMENT_TOOLCHAIN_AND_CRYPTOGRAPHY.md) supply commit, protection and deployment prerequisites.

## D1 — Recognized legacy entry and restart fencing

Offered M-A is a concrete proposed workflow; M-B remains an explicit alternative requiring an additional same-profile initiation/exclusion contract, with UNSUPPORTED_WORKFLOW and no write/task/anchor side effects until that exists and is selected. This is not an owner choice. No generic lost-anchor recovery is permitted. Main's read-only probe distinguishes: (a) verified empty destination; (b) recognized legacy-only mapped source with no protected anchor/P/U/L signatures; (c) protected residue with missing/unavailable anchor; (d) output-only incomplete legacy; (e) mixed/conflicting; (f) unavailable/unsupported. Only (a), plus a separately inspected source (b), may enter M-A. Output-only can be preserved as isolated incomplete acquisition evidence, never initialize an active wallet or qualify complete recovery. Source (c)/(e)/(f) does not become a fresh install.

Explicit initiation is profile.prepareAcquisition({mode:'offline-readonly'}); main's selected trusted file dialog chooses immutable offline source, while the destination is an independently empty, supported slot. No renderer path or caller-supplied source digest. Main builds SourceIdentity from supported namespace/schema inventory, verifies immutable image identity/read-only exclusion, root/output relationships and all frozen/pending/scalar-only namespaces. Unsupported old-writer proof leaves source untouched. Source image and original wallet remain outside the initial destination's managed deletion scope; their subsequent cleanup requires separate qualified ownership/exclusion. No claim is made to stop a separately copied wallet signing elsewhere.

Before keys exist, main stores a nonsecret BootstrapIntent file under the exclusively locked EMPTY destination. It is not trusted authority by itself. Exact schema: {schema:1,id:ID,installation:ID,profile:ID,wallet:ID,candidate:ID,migration:ID,task:ID,mode:'empty-create'|'empty-import'|'offline-readonly',mappingDigest:H,source:SourceIdentity|null,prefix:bytes12,phase:'prepared'|'anchor-published'|'slot-committed'|'profile-anchored'|'ready',version:1}. IDs generated once; path is a fixed package-owned bootstrap slot, not derived from payload. Selected filesystem contract requires exclusive creation, complete write+file barrier, same-volume atomic publish and directory barrier. Crash leaves exact recognized prepare/anchor staging, not an invitation to erase/recreate IDs.

Ordered protocol:

1. Verify empty destination/exclusive native writer and source proof; write/publish BootstrapIntent. No wallet-secret generation/encryption precedes this. If crash occurs before a complete intent, source is intact, destination is bootstrap-incomplete and only explicit resume/cancel inspection is allowed; never silently delete residue.
2. Generate KL once, wrap F1 lifecycle anchor [2,life,installation,intentDigest,KL] with selected provider, write/publish fixed lifecycle anchor after barriers. A lost publication ACK requires re-reading the exact target; it cannot draw another key. Existing anchor context must match the retained intent. If expected anchor is absent but partial/staged wrapped bytes survive, resolve those bytes; otherwise freeze locked/incomplete pending explicit operator recovery. No fresh key overwrites possible prior authority.
3. Unwrap and bind KL; commit initial authenticated L head, slot and bootstrap task/intent in one sync batch. The committed intent digest binds the preceding unauthenticated staging record. Refence/recheck original source before any secret acquisition. If nonsecret prepare data was substituted before anchor publication, context/ownership/source validation must detect it or refuse; same-user hostile host remains outside the stated provider boundary. No claim that a bare prepare file authenticates historical secrets.
4. L records nonsecret profile-init intent and new keyId only; KP is never stored in L; provider-wrapped KP anchor includes exact profile/installation/intent binding. Initialize empty U once under F8 before first encryption; create authenticated empty P/Binding/candidate head, then L profile-ready link. Any cross-store incomplete phase is bootstrap-pending with the original IDs and no active signer.
5. Only now copy verified source into candidate cells under main control, using complete inventory and B4 barriers. Validate bound scalars/scripts/descriptors and root agreement. Activate only after separate trusted activation, policy/capacity acceptance and atomic preservation of old authority where any exists. Cancellation before activation preserves all source and leaves classified candidate/terminal task records; it does not reinstate missing authority or make residue look absent.

Migration body schema2: {schema:2,id:ID,profile:ID,source:SourceIdentity,mappingDigest:H,sourceSchema:U32,sourceInventory:InventoryPageRef[],sourceDigest:H,targetCandidate:ID,phase:'preliminary'|'draining'|'frozen'|'copying'|'verified'|'activated'|'cleanup'|'complete'|'paused'|'conflicting',fence:{kind:'offline-readonly',boot:ID,lease:ID,sourceIdentity:H,drainSequence:U64,inventoryDigest:H},copyCursor:U64,protectedCommit:ID|null,deletions:DeleteItem[],quarantine:Ref[]}. DeleteItem={sourceIdentity:H,key:bytes<=1024,digest:H,intentCommit:ID,state:'intent'|'removed'|'confirmed'}. Deletions are inline closed evidence, not undefined DeletionRef. BootstrapIntent is L's bootstrap body; later slot/supersession bodies are D4. Original acquisition IDs are never inferred from a cache.

Every restart invalidates fence/leases. Before copy, activation or owned-image cleanup, reacquire installation/database exclusion, exact volume/file/schema/origin/partition/namespace mapping and live read-only image proof; re-enumerate and compare inventory, adjusted only for previously committed DeleteItems. New/changed/missing unexpected record or old writer -> conflicting/unavailable, no cleanup. Prior boot's drain acknowledgement is not proof. Protected copy and cursor commit together; missing uncommitted copy can be reconstructed only from refenced source. Unknown head ACK resolves H0/H1 before projection or deletion. After activation, cancellation pauses work but never rolls authority back.

Cleanup of an owned acquired image requires current complete qualified portable recovery, source refence and exact scope; each DeleteItem intent is durable before source deletion, followed by selected source-backend barrier and persisted cursor. Unknown delete ACK: unchanged present retries, absent with authenticated prior intent reconciles, changed/missing without intent conflicts. Completion reprobes all keys. Original externally copied wallet/image is not asserted erased. No unsupported browser storage is treated as native LevelDB. Incomplete/quarantined acquisition retains source and blocks cleanup; read-back is not a power-loss guarantee.

## D2 — Retirement ordering and valid retained graph

Two explicit OD-03D alternatives: R-keep permits logical capability retirement while retaining ALL local private/recovery material under KP; R-remove requires a separately reviewed externalized-graph/archive-resolution design and remains UNAVAILABLE with LOCAL_KEY_RETIREMENT_UNAVAILABLE. No default is selected. R-keep does not claim local key removal, memory forensic erasure or stronger backup privacy. Required complete portable recovery is still mandatory and fully specified, not deferred. Removing individual root/scalar cells, nullable-root shortcuts or accepting dangling Ref exceptions is prohibited.

Retirement={schema:2,id:ID,profile:ID,generation:U32,expectedEpoch:U64,coverageDigest:H,qualification:ID,scopeRefs:Ref[],mode:'retain-local-keys',state:'prepared'|'approved'|'fenced'|'retired-local-kept'|'blocked'|'cancelled'|'expired',commit:ID|null}. This is orchestration only; its fields are duplicated references to existing covered authority, not sole recovery payload. Preparation/approval/fence changes neither catalogue role, logical epoch nor custody members. It may be stored without invalidating a qualified artifact under F6's exact exclusion. Candidate or active generation must first undergo the separately approved replacement/retention path; direct active retirement returns STATE.

| Phase | Guard and atomic effect | Restart/cancel |
|---|---|---|
| prepare | One stable task/Retirement/replay entry; current retained scope and qualification IDs | Read-only prior authority; cancel/expire changes orchestration only |
| approve | Trusted summary states keys remain local, exact generation/scope/current backup and unresolved obligations | Fresh live ceremony; after caller loss reapproval required |
| fence | Close admissions for scope, drain accepted receipts/effects to committed outcomes, pin exact artifact and current graph | Any new accepted semantic event invalidates freeze; no key removal; restart releases stale fence |
| final compare | Authenticate actual artifact, complete original graph/coverage, current scope/policy and independent evidence under writer/file fence; require no quarantine or unaccounted pending event | Mismatch/unavailable/expiry -> blocked, preserving graph and artifact |
| commit | One B4 commit sets role retired-local-kept, updates logical catalogue and Binding consistently, increments epoch, records completion; NO deletion of cells | Resolve unknown ACK before projecting; H0 or full new role, never partial |
| after | Fresh signing and new identity publication from that generation prohibited; current read-only observation/explicit scoped exact-delivery only if already authorized policy permits; reservations/replay remain | Media absent still yields valid local graph and no fresh signing; future complete export uses all retained local material |

First quiescent retirement uses the existing qualified pre-transition artifact once: all semantic role/epoch mutation occurs after the final equality comparison. The post-state deliberately has new coverage and needs a new artifact for a subsequent destructive transition, not another artifact to finish this one. Late scope callback after fence invalidation must be committed and qualification re-evaluated before trying again. A clock/caller/fence change before commit stops it. R-remove emits its typed refusal before task/consent/state mutation, so no unsupported 'retired' success is reported. Planned media-present/absent tests must inspect every root/scalar cell and nested historical operation reference; keeping all keys is an explicit result, never a removal claim. Future archive-removal design must cover externalized references, absent media, all private copies/GC and subsequent full exports before it can be selected/implemented.

## D3 — Content deletion never spends

`ContentRetention={schema:1,profile:ID,generation:U32,message:H,outputs:Ref[],scalars:Ref[],descriptorEvidence:Ref[],operations:ID[],replay:Ref[],reservation:Ref[],policyDigest:H}`. `Tombstone={schema:1,id:ID,profile:ID,generation:U32,scope:'message'|'conversation'|'all-history',messages:H[],retention:Ref[],revision:U64,contentCursor:U64,state:'retained'|'tombstoned'|'removing'|'removed'|'partial',policyDigest:H}`. Each ContentRetention is one message and has<=256 output/scalar/evidence/reservation refs,<=256 operation IDs and<=1024 replay refs; Tombstone has<=100 messages/retention refs and record<=256KiB. All-history/conversation scopes are a B7 delete-content Task over an ordered frozen list of these bounded tombstones; task.detail does not embed that list. The task subject is the first tombstone and links the remaining tombstones through an inventory-page with a closed kind=deletion-index, fields {schema:1,id:ID,kind:'deletion-index',pages:Ref[<=512]}; each pages entry is a tombstone Ref sorted by ID. That page is in membership, is the task.subjectIndex Ref and covers every tombstone before any projection removal. No new untyped page body is allowed. Every message/dialog/conversation/clear-history/wipe-content route delegates to this service, which has **no signer, reservation-create, transaction-forward, broadcast or key-retirement capability**. Never call the current forwarding-before-delete path. No automatic consolidation.

1. Main computes exact retention from raw authority, including frozen/pending/output-only/incomplete-descriptor scalar fallback and existing delivery/replay state. Copy missing required evidence durably; if retention cannot be complete, return RECOVERY_INCOMPLETE and leave content.
2. One B4 commit creates retention references and tombstone membership. Required retention and tombstone are visible together. A failed/unknown commit forbids removal.
3. Remove content in bounded chunks only after resolved tombstone barrier; await backend delete, then commit cursor. Late duplicates check tombstone before projection. New valid monetary observation can be retained silently in protected inventory under existing receipt rules but cannot resurrect content or spend.
4. Restart reconciles tombstone/cursor against actual content. Partial failures report partial, never complete. Restoring an old backup into existing profile merges current tombstones and replay union before activation; conflicts block. A fresh profile without newer tombstones cannot infer deletions absent from that older artifact; document snapshot-time limitation and never claim global deletion propagation.

Pending retention alternatives are now explicit. H-projection removes only the ordinary projection/cache copy and suppresses redisplay; protected Intent.content, received source bytes, exact encrypted/signed artifacts plus retained scalars, audit/provenance and portable copies may still reconstruct the message/publication. H-hidden retains projection bytes too but marks them hidden. Both retain required recovery, differ only in the redundant projection copy, and MUST say 'hidden; recovery content retained', not irreconstructable deletion. The former minimum-content label is withdrawn as an implementation claim: a true C-compact alternative returns CONTENT_COMPACTION_UNAVAILABLE until a separate terminal-compaction/commitment design is reviewed and selected. This visible scope limitation needs owner/review consideration, not implied acceptance. No settled-status shortcut removes immutable intent or exact bytes.

Pending delivery policy remains retain exact artifact with suppressed content or block until settled; neither discards unresolved evidence/reservations. Received messages' raw source records, derivation evidence and retained keys can reconstruct plaintext; encrypting that data at rest does not mean content is gone. The trusted summary lists these categories and whether existing exported artifacts/older backups retain content. A fresh restore of the current artifact must honor its tombstones while an explicit recovery inspector can still reconstruct retained content. An older backup without later tombstones cannot infer global deletion. Current-profile merge must union validated tombstones before projection. Remote deletion remains unavailable until separately reviewed non-spending protocol/consent exists. All routes, including wipe-content, have zero signing, reservation creation, forwarding and broadcast. Complete whole-profile destruction is a different operation with surviving L and external backup limitations.

## D4 — Destruction evidence outside the deleted profile

Surviving domain: installation lifecycle database `L` and immutable DPAPI-wrapped random lifecycle key `KL`, separate from profile authority database `P` and profile root-wrapping key `KP`. L contains only installation/profile-slot identity, scope digests, phase/cursors and supersession links; no wallet keys, mnemonic, content, transaction bytes or password. KL cannot decrypt P. KL, its wrapped anchor and L are explicitly **excluded** from managed-profile destruction and shown in trusted scope. They survive to authenticate terminal evidence. If unavailable/corrupt, destruction completion is blocked, not guessed. No forensic erasure or entire-installation deletion promise. Removing L/anchor manually is outside managed operation and must not turn surviving residue into absence.

`LifeHead={schema:1,installation:ID,revision:U64,currentProfile:ID|null,slotEpoch:U64,records:LifeRef[],pending:ID|null}` authenticated per F1. `Destruction={schema:1,id:ID,installation:ID,profile:ID,slotEpoch:U64,scopeDigest:H,managed:[{storeId:ID,mappingDigest:H,kind:'authority'|'projection'|'legacy-owned'|'temp'|'credential-wrapper',status:'present'|'removing'|'absent'|'unavailable'}],excluded:Text(256)[<=128],evidence:DestructionEvidence|null,phase:'prepared'|'approved'|'fenced'|'irreversible'|'removing'|'terminal'|'blocked'|'cancelled',cursor:U32,approvalSummary:H,terminal:ID|null}`. Store lists<=128; source file paths resolved from main mapping; no renderer path. Life records use atomic sync batches and B4 outcome resolution within L.

Whole-profile destruction requires current complete independently verified backup by this proposal; absence/quarantine/unresolved policy blocks it. A request to destroy the last unrecoverable material requires a separate owner policy/design, not implied permission. The scope includes owned candidate/quarantine/migration/temp stores and profile KP wrapper; external exports, OS backup/swap/dumps/old residual copies remain excluded. No terminal with inaccessible managed store, even if key wrapper already absent.

| Phase/edge | Ordered action and crash result |
|---|---|
| prepare | L scope record committed; P unchanged; cancellation allowed |
| approve | Trusted full scope/current qualification consent; consumed approval saved L; cancellation still allowed |
| fence and final guard | D6 below closes admission, drains accepted work, recomputes exact scope/coverage and reauthenticates stable available artifact; changed scope requires new consent. No deletion before guard and resolved L intent |
| irreversible | Atomically commit L irreversible plus DestructionEvidence after final guard under the same fence; startup consults L first and blocks P even if P still says ready |
| remove managed stores | For each store commit L remove-intent; logical remove using selected barrier; reconcile explicit absence; commit L cursor. P and KP may be removed only after this durable L intent. KL/L never in list |
| lost remove/cursor ACK | Reopen exact mapping: absent with prior intent -> account, unchanged present -> retry, replaced/unknown mapping -> blocked; never act on substituted directory |
| terminal | Reprobe every managed scope absent after selected barriers; one L commit sets terminal ID and slot destroyed; report logical managed-store deletion only |
| cancel after irreversible | Refuse cancellation; continue named recovery or report blocked. No profile reactivation |
| missing provider/anchor | Return locked/unavailable, preserve L/copies; no setup or completion |

Old copied terminal record cannot select a different installation/profile/slot: authentication/bindings fail. A full self-consistent restored L+anchor/profile set is not a detectable freshness attack under this local design; G claim boundary applies.

Explicit new-profile supersession: trusted request binds old terminal ID and current LifeHead revision. Commit L `Supersession={schema:1,id:ID,oldProfile:ID,terminal:ID,newProfile:ID,newSlotEpoch:U64,state:'prepared'|'committed'|'cancelled'}` before preparing new profile P2. P2 becomes a validated inactive candidate under new KP; old terminal remains intact. Atomic L commit changes currentProfile to P2 only when P2's bootstrap head is durably verified. Crash before L switch leaves old destroyed slot plus recoverable prepared successor; after L switch B classifies P2 candidate-only. Later B activation is separate. Cancel before switch keeps terminal and cleans only new candidate; after switch ordinary candidate cancel applies. Reducer follows authenticated current slot and supersession link, so old terminal neither becomes absence nor permanently blocks P2. Concurrent new-profile requests serialize, stale terminal/slot fails.

## D6 — Final destruction freeze and surviving evidence

This guard is mandatory after approval and before the irreversible L commit. Earlier qualification or a digest cached at approval is insufficient. Destruction evidence carries no mnemonic/scalar/content/password/KP, and KL cannot decrypt P. The opaque coverage/file commitments and local mapping identities still disclose limited lifecycle/linkability metadata; owner logical-deletion/privacy choices must acknowledge that surviving scope.

~~~text
FrozenScope={schema:1,installation:ID,profile:ID,slotEpoch:U64,
 registryRevision:U64,stores:[{storeId:ID,kind:StoreKind,mappingDigest:H,
 volume:bytes16,file:bytes16,locator:Text(4096),expected:'present'|'absent'}],
 excluded:Text(256)[<=128],digest:H}
DestructionEvidence={schema:1,destruction:ID,scope:FrozenScope,
 authorityEpoch:U64,headRevision:U64,coverageDigest:H,policyDigest:H,
 artifactDigest:H,artifactBytes:U64,artifactVolume:bytes16,artifactFile:bytes16,
 verificationVersion:2,complete:true,acceptedSequence:U64,drainedSequence:U64,
 pendingAccepted:0,summaryDigest:H,consume:ID,guardCommit:ID}
~~~

StoreKind is the D4 managed kinds; stores sorted by storeId, unique and bounded128. locator is a main-validated canonical path relative to the accepted fixed package/profile root or an explicitly enumerated owned image, with no reparse traversal; no renderer path. Stable volume/file/mapping plus location are retained in L so removal can resume after P is gone. digest=D(scope,all FrozenScope fields except digest). DestructionEvidence is authenticated as part of the complete L record, not an unkeyed substitute. Full coverage bytes remain in the encrypted artifact; L preserves the exact nonsecret digest/evidence class without recovery secrets. Paths/counts/commitments surviving destruction are disclosed, not called erased.

1. Hold exclusive installation/main writer and freeze scope registry, new task/admission/network reads/dispatch/temporary-store creation. Revoke live grants except this scope-bound destruction ceremony. Drain every pre-freeze accepted event to durable records or durable unknown-outcome obligations; no buffer is dropped as 'cancelled'. Record accepted/drained sequences and pending count. Unresolved operations must satisfy the selected inclusive/blocking coverage policy.
2. Under that fence, enumerate ALL current managed authority/candidate/quarantine/temp/projection/owned-image/KP-wrapper stores and exact identities. Compare with the trusted summary. A new/changed scope requires refreshed owner-visible ceremony, not merely replacing scopeDigest. Late accepted receipt/effect/tombstone/policy mutation makes the fence dirty; release, commit evidence and rebuild qualification/consent as required. After the final seal, unadmitted external events receive no acceptance ACK; prior external uncertainty remains durable and covered. No new store can register after seal.
3. Recompute current F6 coverage after drain. Open the exact independently retained artifact with selected stable file identity and proven write exclusion, read/authenticate its full bytes/graph and compare current complete coverage. Verify its storage domain is outside the managed deletion scope and cannot disappear through this operation. Artifact missing/replaced/modified, unsupported provider, changed policy, incomplete recovery, expired ceremony or unproved exclusion blocks. Recheck guard status immediately before submission. A simple path or old qualification boolean is insufficient.
4. Persist P's freeze/guard bookkeeping (excluded only as orchestration), then one atomic sync L batch stores irreversible DestructionEvidence and the consumed original scope authorization. Keep the writer/registry/artifact fence through resolved L acknowledgement and the removal phase. No profile/store deletion until L outcome is resolved committed. An unknown L ACK freezes P and resolves the exact prior/new head; no guessing. A crash after P's bookkeeping but before committed L intent returns to reversible paused state with every byte preserved.
5. Each removal intent/cursor still follows D4 and matches FrozenScope identities. Inaccessible/substituted store blocks terminal success. On restart all leases are invalid: reauthenticate L, reacquire exact scope/artifact exclusion and request the backup credential through a dedicated trusted resume-input task if needed. Verify the SAME artifact bytes and committed pre-destruction coverage from L; never invent a newer smaller scope because P is partly gone. Missing media/provider/credential blocks further removal while preserving remaining stores. The durable irreversible intent authorizes only its original scope, not fresh wallet actions. Cancellation after it is unavailable; before it follows the owner-selected cancellation boundary.
6. Terminal requires every bound managed item accounted absent through selected barriers, then one L terminal/slot update. KL/L and external artifacts remain excluded. New-profile supersession is a separately prepared task, links the authenticated terminal and keeps its evidence. No old marker deletion to simulate absence and no automatic new wallet.
