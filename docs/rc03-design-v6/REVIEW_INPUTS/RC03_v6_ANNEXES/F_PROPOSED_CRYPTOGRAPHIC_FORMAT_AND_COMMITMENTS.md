# Annex F — Concrete protection and portable-container proposal

Version `6.0.0-draft`. **Unselected integration proposal; no adoption or implementation authorization.** Existing cryptographic library constructions are used as proposed building blocks; no replacement cipher, KDF or ratchet is specified. Independent Cryptography and external human integration review are prerequisites to adopting this format/key hierarchy, sensitive reliance and recovery-dependent retirement. [B](B_LIFECYCLE_REVISIONS_AND_COMMITS.md), [C](C_OPERATION_AND_EFFECT_TABLES.md), [D](D_MIGRATION_AND_DESTRUCTION_RESTART_TABLES.md) and [E](E_DESCRIPTORS_AND_COMPATIBILITY.md) supply semantic schemas.

## F1 — Canonical records and key hierarchy

Proposed canonical encoding `C(x)` is RFC8949 core deterministic CBOR (§4.2.1): shortest definite lengths/integers, map keys sorted by bytewise lexicographic order of their deterministic encodings, never the alternate length-first convention. No tags, floats, undefined, indefinite lengths, duplicate keys, unknown fields or noncanonical equivalents. Map keys are exact ASCII field names from the closed schemas; enums are exact text; text valid UTF-8 with no implicit normalization. Arrays preserve declared semantic order; sets explicitly sort as below. Internal U64/Sat/revisions are CBOR unsigned integers, not decimal text; IPC decimal strings are range-checked then converted losslessly. IDs decode to16-byte bstr, H to32-byte bstr, cryptographic keys/scripts/data are bstr, booleans/null as declared. Every optional map field is **absent** when not present, not encoded null unless schema explicitly permits null. Code/schema notation has no effect on these wire types. Decoder re-encoding equality is checked within bounded resources before accepting canonical input. [RFC8949](https://www.rfc-editor.org/rfc/rfc8949.html#section-4.2.1).

`RecordPlain=[1,type:tstr,id:bstr16,revision:uint,context,body]`; `context=[profile:bstr16,wallet:bstr16,generation:uint,network:tstr,purpose:tstr]`. Profile-wide records use generation0xffffffff and wallet=manifest wallet ID; actual generation allocation excludes0xffffffff. Lifecycle context is `[installation:bstr16,slotEpoch:uint,'installation-lifecycle']`, with separate record class/key. Body must match the B7 closed logical-type registry and referenced B/C/D/E/F schema. RecordPlain remains the logical origin envelope; actual main-owned storage uses F4 CellPlain plus authenticated Binding. Native and restored profiles use the same separation. Profile-wide records cannot be used as per-output key records. Purpose equals registered type purpose, not a caller string.

`D(label,x)=SHA256(C([label:tstr,x]))`; Record and output-binding labels remain literal finney.rc03.record.v1 and finney.rc03.output-binding.v1. F11 is the authoritative dictionary for all other commitments; obsolete implicit labels do not define a preimage. Record Ref digest is D(record,RecordPlain), **not local ciphertext digest**. Membership page is `{schema:1,page:ID,entries:[[type,id,revision,recordDigest]...]}` sorted by raw UTF-8 type bytes then raw ID bytes, unique `(type,id)`, <=1024 entries and256KiB; pages are sorted by first membership key, disjoint and complete. Manifest references page plaintext digests. Membership excludes the manifest itself and membership-page nodes, which are anchored by head and manifest respectively, preventing recursive self-hashing. Duplicate/missing/extra committed membership fails. References plus object lookup keys use expected profile/type/id/revision, never an arbitrary storage path. Intent digest is F11's versioned exact Intent commitment; aliases sort by network/txid bytes/vout numeric; effect dependency sets by raw ID; original input/output/encounter/transaction order never sorted away. Type-purpose mapping is exact: root -> legacy-wallet-root, scalar -> output-recovery, sender-ephemeral -> stealth-sender-recovery, every other profile RecordType -> its identical type token. A BoundKeyRef spending/identity purpose is additionally checked against that record's allowed use; it never rewrites the stored purpose. Root/output/scalar context generation is its actual generation; profile-wide catalogue/manifest/policy/membership pages use the reserved profile-wide value; all other records carry their owning generation or the explicit profile-wide value according to the declared body scope.

Proposed Windows chain of protection:

1. Generate independent random32-byte `KL` per installation and `KP` per profile using OS-backed CSPRNG. DPAPI/current-user via pinned Electron safeStorage wraps **separate** canonical anchors encoded as base64 text: `[2,'life',installationId,bootstrapIntentDigest,KL]` and `[2,'profile',installationId,profileId,profileInitIntentDigest,keyId,KP]`. Validate embedded context against selected installation slot after unwrap; exact bytes/length only. Wrong-account/unavailable/corrupt refuses. No plaintext fallback. Anchors held in distinct lifecycle/profile storage domains. Protected expected installation/slot comes from authenticated lifecycle head, not a replaceable record's self-description. Initial installation identity depends on controlled package mapping and successful absence probe; same-user host compromise and complete self-consistent rollback remain outside claims.
2. Standard HKDF-SHA256 (RFC5869), IKM=KP, salt=profileId16, info=ASCII `finney.rc03.profile.record-aead.v1`, output32 gives `Krecord`. Separate info `finney.rc03.profile.head-mac.v1` gives `Khead`; `finney.rc03.profile.journal-mac.v1` gives `Kjournal`. KL with salt=installationId and info `finney.rc03.life.head-mac.v1` / `finney.rc03.life.record-mac.v1` derives lifecycle keys. No wallet/identity scalar or mnemonic is a storage/backup key. Standard Node crypto HKDF/HMAC/AES-GCM in pinned packaged runtime is the proposal; runtime/OpenSSL versions must be recorded. [RFC5869](https://www.rfc-editor.org/rfc/rfc5869.html).
3. Actual storage envelopes are [2,context,type,id,revision,nonce:bstr12,ciphertext:bstr,tag:bstr16], type exactly cell, binding, binding-page, physical-members, authority-page or physical-manifest. Plaintext is C([2,type,id,revision,context,body]); body matches that exact physical schema below/B7. D(label,whole plaintext) uses finney.rc03.cell.v2 for cell, finney.rc03.binding.v2 for binding, finney.rc03.binding-page.v2 for binding-page, finney.rc03.physical-members.v2 for physical-members, finney.rc03.authority-page.v2 for authority-page and finney.rc03.physical-manifest.v2 for physical-manifest. Purpose equals physical type; non-cell physical records use profile-wide generation. AAD is exactly C(['finney.rc03.record-aead.v2',2,context,type,id,revision]). AES-256-GCM Krecord and16-byte tag remain unchanged. F8 authenticates and consumes a fresh random96-bit nonce permission BEFORE every encryption attempt, including aborted/uncommitted staging; maximum2^24 reservations per profile key, no reset/rekey fallback. Exact-envelope reuse is not another encryption. Context and committed physical Ref digest must match after decryption. Logical RecordPlain hashes remain version1 and never masquerade as physical-cell hashes. This explicit schema/AAD version revision needs new independent vectors and external integration review; no primitive or wallet-wire derivation changes.
4. Authenticated head [2,installationId,profileId,revision,physicalManifestId,physicalManifestDigest,commitId,mac] uses HMAC-SHA256(Khead,C(preceding fields)). PhysicalManifest names the BindingRef, exact physical members and logical authority snapshot; Binding anchors each original envelope through its expected CellRef. B4 journals use HMAC-SHA256(Kjournal,C(['finney.rc03.commit.v2',Commit])). Membership never relies on replaceable self-authentication. A prepared journal cannot promote stages absent the atomic committed head/result. Original logical membership pages remain source evidence; physical member closure is checked independently.
5. L records use `[1,installationId,slotEpoch,type,id,revision,body,mac]`, HMAC with lifecycle-record key over preceding fields; L head uses the exact LifeHeadEnvelope and lifecycle-head MAC preimage in F11. Only nonsecret D4 metadata lives there, no KP. Atomic sync L head/member update anchors expected lifecycle revisions. Deleting KP/P cannot erase KL/L. Whole L+anchor valid rollback remains a stated limit. Installation identity or anchor substitution from another installation conflicts; loss never generates a replacement key over residue.

Local encryption keys/DPAPI blobs and nonce accounting are never portable. F4 defines the complete original logical envelope and total physical binding; every original reference validates before binding. F6 defines exact semantic coverage. F8 supplies pre-use nonce permission for every physical-cell encryption. No imported approval/continuation is executable.

## F3 — Pending credential and privacy alternatives

Both credential alternatives share encoding1: valid UTF-8 bytes of entered Unicode string **without normalization, case folding, trimming or newline conversion**; reject NUL/unpaired surrogates; preserve all permitted whitespace and compare confirmation byte-for-byte. BIP39 normalization is unrelated. Import min1/max1024 bytes to recover supported historical P4 artifacts; export policy stricter below. Trusted channel only, no logging/string-copy erasure guarantee.

Credential G: main generates32 random bytes, displays64 lowercase hex characters through A8 trusted.showGeneratedCredential in the isolated trusted UI, password bytes are those64 ASCII characters; confirmation before export, independent of mnemonic. Credential H: user-entered passphrase16..1024 UTF-8 bytes, twice confirmed with visible whitespace/encoding notice and offline-guessing warning; no claim length guarantees entropy. Either uses same exact KDF; weak human input never causes lower costs. Owner must choose G or H, storage/transfer guidance and recovery-device envelope. Generated secret itself is never in clear header or clipboard by default.

Privacy alternative P-min uses the exact F2 header with flags0 and raw Portable bytes. It leaks format/suite/KDF/byte length and equality of identical copied files, but no deliberate stable clear identity. P-pad flags1 uses the same cipher suite and encrypted closed wrapper {schema:1,data:bstr,pad:bstr}; data is exactly C(Portable), pad is OS-random bytes. No normalization, compression or plaintext identifier is added. Both policies remain pending; parser accepts only explicitly selected/allowlisted flags, never silently falls back to flags0 after padding failure.

Exact padding rule: h(n) is the deterministic CBOR byte-string length-header size:1 for0..23,2 for24..255,3 for256..65535,5 for65536..4294967295,9 beyond. L(d,p)=18+h(d)+d+h(p)+p. The constant18 is the map header, encoded keys data/pad/schema and schema value1. Let B=1048576. Starting k=ceil(L(d,0)/B), examine k up to128 in ascending order. For each h band solve p=kB-18-h(d)-d-h, accepting only nonnegative integer p in that band's interval. Choose the first feasible k and its unique p. An unreachable nearest bucket is SKIPPED; later feasible bucket is not 'nonminimal'. If none exists by128MiB, return PADDING_CAP with zero publication/activation, preserving source. Decoder independently recomputes this exact minimal feasible pair after authenticated canonical parsing, rejects any other bucket/pad length, and charges wrapper/data/pad resources before allocating. Length alone is not authority to allocate. PayloadSchema3 and inner format6 are checked before qualification.

Proposed arithmetic fixtures, not independently verified encoding vectors: d1048529/p23 ->1048576; d1048527/p24 ->1048576; d1048296/p255 ->1048576; d1048294/p256 ->1048576; d983015/p65535 ->1048576; d983012/p65536 ->1048576. Gap d1048528 has totals1048575 at p23 and1048577 at p24; choose next bucket2097152,p1048596. Likewise d1048295 and d983013/983014 skip the unreachable first bucket. d134217680 cannot reach the128MiB bucket and the next is beyond cap: PADDING_CAP. R96 limits legitimate source payloads so its largest required bucket is97MiB. Exact encoded bytes/digests remain UNVERIFIED until independent implementations test them; this assignment checks only the stated integer arithmetic, not a CBOR/crypto harness.

P-pad conceals fine size only, leaks the chosen1MiB bucket and format, and may jump an additional bucket at a header-width gap. File names/OS metadata and identical-copy equality remain visible. Credentials and padding are owner choices; changing a credential cannot revoke old artifacts or copied signing keys.

## F4 — Lossless logical graph and total local binding

This version proposes payloadSchema3 and container format6; it is incompatible with the unimplemented format4/5 drafts. Suite/KDF1 and the cryptographic primitives are unchanged. There is no format4/5 fallback or inferred upgrade. The following representation replaces body-only dedicated collections. Every record, including an unreferenced Replay or Reservation, carries its complete original envelope exactly once. No decoder infers envelope metadata from incoming references.

Closed types (all integer/byte types use F1 canonical encoding):

~~~text
OriginSpace={schema:1,id:ID,profile:ID,wallet:ID,network:Network}
QRef={space:ID,ref:[type:RecordType,id:ID,revision:U64,digest:H]}
PortableRecord={space:ID,original:RecordPlain}
PortableAuthority={schema:2,epoch:U64,manifest:QRef,writerSpace:ID,policy:QRef,
 generations:[{space:ID,generation:U32,role:Role}],
 current:QRef[],historical:QRef[]}
Role=0(candidate)|1(active)|2(retained)|3(retired-local-kept)
Portable={format:6,suite:1,payloadSchema:3,credentialEncoding:1,
 spaces:OriginSpace[],authority:PortableAuthority,records:PortableRecord[],
 coverage:{schema:3,bytes:bytes,digest:H},complete:boolean}
~~~

At most16 spaces/generations combined,65536 records (including historical versions and supporting pages), and the F5 charged-byte cap. Arrays spaces/generations are sorted by space bytes then generation; records by (space,type UTF8,id bytes,revision numeric). No duplicate qualified envelope key, even with equal bytes. Current contains one version per (space,type,id); historical contains all additional versions needed by any retained Ref, and no duplicate current member. Both reference arrays sort by the same key. Unknown types/versions/context/fields reject. A RecordPlain's source profile/wallet/network must equal its OriginSpace; its logical generation/purpose must match its body and the type registry. Current and historical membership enumerates every exported record exactly once, including records with no incoming references. Closed-reference traversal may not silently omit an unreferenced replay/observation/tombstone. Original local membership pages and their raw digests are included if referenced, as are complete raw-source/audit/artifact chunks. Operating-system anchors, encryption keys, nonces, usage ledgers and live grant secrets are not RecordPlain and are never portable.

Every local Ref is first resolved in the containing record's OriginSpace; explicitly qualified QRefs use their stated space. F10 RRef is admitted at every logical Ref slot, before physical transformation. Exact type/id/revision/context and D(record,original) must match. ID-only edges are not guessed Refs: their target type and current/historical interpretation are specified in B7. A missing, duplicate, ambiguous or substituted target rejects completeness and leaves the source intact. Digest Ref edges must form a finite DAG; cycles through IDs are permitted only through the exhaustive typed back-edge registry in F10, with no recursive digest dependency. All original envelopes are validated before constructing local bindings. An authenticated file authenticates these supplied original bytes; it does not prove their past on-chain existence or possession of the originating OS key.

Local restoration uses explicit indirection instead of rewriting immutable intent/artifact bytes. Physical profile/wallet IDs and keys are fresh; logical source IDs and original request/intent provenance remain unchanged. The exact local representation is:

~~~text
CellPlain=[2,'cell',localId:ID,localRevision:U64,localContext,
 {space:ID,original:RecordPlain,originalDigest:H}]
CellRef=['cell',localId:ID,localRevision:U64,cellDigest:H]
Binding={schema:2,profile:ID,wallet:ID,incarnation:ID,prefix:bytes12,
 spaces:OriginSpace[],pages:PhysicalRef[],nextOrdinal:U32,
 generations:[{space:ID,logical:U32,local:U32,role:Role}],
 authorityEpoch:U64,active:U32|null}
~~~

localContext uses F1's profile/wallet/mapped-generation/network/purpose='cell'. CellDigest=D('finney.rc03.cell.v2',CellPlain). The outer AES-GCM record encoding, AAD and expected head are version2 and bind that exact physical context; key derivation labels, nonce size, tag size and algorithm remain as F1. A native new profile uses the same logical-record/cell separation, so subsequent restore does not nest a previous CellPlain or recursively copy old physical bindings. Logical envelope revisions survive export and import; physical localRevision initially1. Physical encryption counters are fresh only because KP is genuinely new in a separately admitted destination, never by resetting an old profile. Original graph bytes cannot be passed directly to the signer as local authority.

Deterministic binding algorithm, given the once-persisted candidate identity/prefix: (1) validate the entire original graph; (2) sort original qualified keys as above; (3) for ordinal i starting1, assign localId=prefix12||uint32be(i); verify prefix uniqueness in the selected destination; (4) sort logical (space,generation) pairs and assign local generations0..15; profile-wide0xffffffff stays reserved; (5) compute each CellPlain/CellRef independently of the binding table; (6) build the bijective from/to table and generation table, authenticate them from the new head; (7) expose only the inactive candidate. Restart uses the same committed prefix/IDs; unknown preparation never allocates a second mapping. Imported same-body records at different revisions remain separate validated entries, not collapsed by their body. Repeated imports of overlapping roots/outpoints use the existing ownership-conflict/alias checks, not parallel signing authority.

Total reference transformation T is a main-internal typed view: every logical Ref/QRef becomes its exact CellRef through Binding; every logical profile/wallet/generation field in a current-purpose request/view becomes the corresponding physical binding; ID relationships resolve the B7 declared logical target then T. Cryptographic scripts, txids, scalar bytes, derivation paths/encounter ordinals, original RequestBinding, exact Intent/Artifact bytes and historical provenance are immutable origin data, not locally rewritten signatures or approvals. The view carries both OriginKey and current BoundKeyRef; a purpose-specific main operation must validate the local binding, origin envelope, current generation role, caller and fresh authorization. No ambiguous untyped string is treated as a reference. A new mutation serializes a new logical envelope through the inverse declared mapping; original immutable intent/artifact/history is never rewritten. Its new Cell and Binding update share B4's atomic commit. No generic original-record access or raw-key IPC is introduced.

Approval/continuation/task/external states in original records are historical evidence after restore. membership in Binding.imported plus a new installation/boot/epoch means no imported consume ID, grant, task or continuation is executable. Recovery imports classify every operation through C's uncertainty reducer, retain reservations/replay, and require A's explicit current recovery ceremony before exact-byte delivery. No shell launch or deletion resumes from imported tasks. Local admission state is candidate until explicitly activated; PortableAuthority's role is snapshot evidence, not permission to activate. Every nested reference has the same validated transformation, including supporting pages and unreferenced current records. Complete fresh-profile reconstruction uses only this package, its credential and the new provider: no original OS keys, physical cell files or relay history.

Binding pages are {schema:2,id:ID,ordinal:U32,entries:[{from:QRef,to:CellRef,imported:boolean}]} with <=1024 entries and <=256KiB each. Binding.pages contains <=65 sorted contiguous-ordinal PhysicalRefs and no missing/duplicate from/to key. The imported flag is stored only in the corresponding page entry. References to Binding.imported denote that authenticated flag view, not an extra root field. Binding root <=64KiB. Physical member pages are {schema:2,id:ID,ordinal:U32,entries:PhysicalRef[<=1024]}, <=256KiB; each member appears once. PhysicalManifest references <=128 pages, excluding itself and those page nodes from entries to avoid self-hashing. All pages are directly authenticated by the manifest's refs; Binding and every cell/page are accounted once. Authority index is also paged: AuthorityIndex={schema:3,epoch:U64,manifest:QRef,writerSpace:ID,policy:QRef,generations:[{space:ID,generation:U32,role:Role}],currentPages:PhysicalRef[<=64],historicalPages:PhysicalRef[<=64]}. AuthorityPage={schema:2,id:ID,ordinal:U32,kind:'current'|'historical',entries:QRef[<=1024]}, <=256KiB, type/purpose authority-page. Current/historical together enumerate <=65536 original envelopes once. PhysicalManifest.logicalAuthority is this bounded AuthorityIndex; flattening its authenticated contiguous sorted pages yields exactly PortableAuthority. Pages themselves are included in physical member accounting. No monolithic1MiB mapping/authority array is required. Each initial binding entry's flag is true on import, false on native creation. Later native records are false; original imported approvals remain inert even after legitimate new operations. New local ordinals append from nextOrdinal under the same atomic head and increment without reuse; overflow blocks, never renumbers live references. F12 selects the native writer's logical namespace independently of the new physical profile. Native RRefs/QIDs preserve imported target namespaces; no original ID is silently aliased or rewritten. Sixteen-space restore does not require a seventeenth space.

The binding table maps source-scoped contexts; the selected Manifest2/Catalogue2 and its agreement with AuthorityIndex/Binding govern current ownership roles under F12. A supplied source namespace is never permission to choose another live profile. Adoption of this cell/binding integration is a design proposal requiring the designated reviews and external human assessment; document validation does not validate its implementation.

## F5 — Compositional recovery and parser budget

Supported-capacity proposal R96 (OD-02G) or explicitly unavailable larger-capacity design; neither is owner-selected. This replaces the incompatible independent64/128/256MiB admission promises. Protocol ceiling remains128MiB plaintext,2049frames and134260821 file bytes; the supported application's complete Portable representation must fit a stricter charged96MiB envelope before it admits obligations. An otherwise authentic larger artifact returns CAPACITY_UNSUPPORTED, preserves source and cannot be called complete locally. Larger support needs a versioned budget/device proposal, not silent truncation.

Charge is exact canonical Portable length with every mutable unsigned integer conservatively charged9 bytes, each supported role/state at its maximum declared encoded width, plus reserved future-obligation bytes. Include original envelope wrappers, all original/historical graph/source/audit/provenance records, spaces, authority, coverage bytes/digests, complete raw artifacts, tasks and tombstones. Duplicate physical/semantic caches are not portable but their local cost is separately bounded. No compression, omitted historical material or raw Ref guessed from another record reduces the charge. Count ceilings are65536 logical records and sixteen logical generations/spaces, subordinate to96MiB. Current charged bytes + irrevocably reserved future credits <=100663296 at every admitting commit.

For canonical raw payload length d<=96MiB, P-min plaintext=d; P-pad uses F3, whose largest possible supported result is97MiB. Thus maximum supported ciphertext file is64+101711872+1553*21=101744549 bytes. The format's128MiB ceiling remains a rejection bound for externally supplied input, not permission for Finney to accumulate unrecoverable local obligations. The 2200*65536=144179200-byte example fails admission before creating that state, even without wrappers. It is never fixed by filtering the eventual backup.

Physical materialization budget: original Portable<=96MiB plus <=1024 extra encoded bytes per logical record for cell/context/local map/membership and <=8MiB fixed head/catalogue/indices is at most168MiB for65536 records. Candidate hard logical cap192MiB therefore leaves24MiB margin; exceeding the exact1024-byte overhead contract rejects before admission and requires design revision, not an allocation exception. Cell wrappers have bounded IDs/context and contain each original envelope once; bindings contain no duplicate original bodies. Native/stage exact bytes are measured against this bound. Import can retain one encrypted input<=101744549, two192MiB candidate/stage copies, and16MiB I/O reserve: total<=521174949 bytes, below512MiB=536870912. No third full copy or plaintext temporary file is permitted. Export needs one frozen pin and one ciphertext temp plus final publication through same-volume rename; it cannot double-copy unnoticed. Native DB/WAL/compaction filesystem amplification is a separate measured physical-space prerequisite, with a proposed2GiB reserved workspace and1GiB authority quota; failing actual backend reservations yields UNAVAILABLE without claiming durability or deleting source. The512MiB figure bounds accounted logical staging, not arbitrary storage-engine amplification.

The96MiB charge includes8MiB emergency captured-evidence reserve. New owner-originated obligations stop at88MiB inclusive of all held credits. At most eight incoming reads are armed; each reserves1MiB raw frame plus bounded conversion/evidence credit before read, and count/byte/nonce/staging credits must all fit. No unbounded socket buffers. A new outgoing operation reserves its exact final artifact upper bound (<=8MiB) plus4MiB future-effect credit and64 total attempts; retained data across all effects may not exceed this credit. New dispatch stops before its reserved evidence capacity is exhausted. Unexpected allowed input is encrypted into a bounded observation/quarantine record, classified capacity-incomplete and pauses new admission; it is included in backup, never silently dropped or counted complete. Before reserving the next read, ensure remaining evidence/nonce space; if none, stop reading/acknowledging and report incomplete capacity. Unlimited future network evidence and unsolicited post-close delivery are not promised. Exact duplicates may reuse existing byte-identical evidence, but no distinct uncertainty may be evicted. If storage/nonce exhaustion prevents persisting already read bytes, hold only the bounded pending buffer, emit failure without acceptance acknowledgement and freeze; do not claim that receipt durable or recovery complete. Original acquisition images/artifacts stay untouched when they exceed these limits.

Import/export concurrency one active/one queued per installation. Header preflight exact64bytes; protocol counts/lengths/KDF tuple checked before expensive work. KDF64MiB, isolated worker cap256MiB, decoded live-object cap64MiB, installation-accounted working-memory cap384MiB including clones and buffers; incremental parsing avoids materializing all records in RAM. Decoder depth16 for individual records, maximum2,000,000 nodes, fields<=64 per map, text<=65536 (raw record<=1MiB), same schema count caps. ## F8 — Authenticated pre-use nonce accounting

AES-GCM uses the same random96-bit nonce construction and2^24 lifetime upper bound; this is a proposed accounting mechanism, not a new nonce generator or rekey policy. One main encryption service owns Krecord for a profile; workers receive no reusable key or nonce ticket. KP has immutable keyId=profile anchor's main-generated ID, bound by L. Profile usage occupies a separate namespace U in the SAME native DB as P, outside graph-head rollback/GC. U is authenticated with Kjournal and domain labels below; it is plaintext nonsecret metadata (nonces/counts/purpose hashes), never recursively AES-encrypted.


Entries and child ranges sort by nonce bytes, unique disjoint ranges. Tree height<=5, count sums exact, nonempty children; empty initial root is an explicit leaf with count0 and min=max all-zero12 sentinel, never a usable nonce. Digest=D('finney.rc03.usage-node.v1',node); authenticated UsageHead MAC is HMAC-SHA256(Kjournal,C(['finney.rc03.usage-head.v1',head fields excluding mac])). Initialization occurs once after a new KP anchor is durably tied to L's profile-init intent and before any encryption. Legacy migration acquires a genuinely new destination KP; no existing key is regenerated over residue. Source key usage is never imported to authorize a new profile, and copied protected stores are unsupported acquisition.

## F12 — Imported inputs and new native authority

OriginSpace is a logical naming context, not a claim of current OS/profile/caller authority or of who authored later revisions. F4 preserves original envelopes exactly; F10 resolves RRef/QID before applying Binding. A source approval never becomes local permission. Local profile/wallet IDs, physical generations, current epoch and authenticated caller are derived from the current PhysicalManifest, Binding and boot. Original RequestBinding/CallerBinding fields retain their actual creation-time facts. The runtime compares a native request with these current physical facts, not with an imported OriginSpace name.

GKey={space:ID,generation:U32} with generation !=0xffffffff identifies a logical wallet generation. Local generation is Binding.generations' unique mapping for GKey; tuple not just integer is the lookup key. PortableAuthority generations are unique GKeys, sorted space then generation, <=16, exactly one active or none. At most16 distinct OriginSpaces, including namespaces containing only profile-wide coordination records; the phrase spaces/generations cap means BOTH counts <=16, not an assumed one-generation-per-space. Source/output/root context must match the named GKey. No ambiguous search for a numerically equal generation occurs. RootAlias hashes can identify equality only after validating original roots; aliases do not activate a retained generation or authorize new signing from it. Whole-network canonical outpoint indexing across ALL spaces prevents duplicate reservation under alias IDs; conflicting ownership/script/value is quarantined, not resolved by namespace choice.

The current logical coordinator is PortableAuthority.manifest, a QRef to Manifest schema2. Manifest2 has exactly B3 Manifest fields except schema=2 and active=GKey|null. Its catalogue refers to Catalogue2={schema:2,entries:Generation2[<=16]}; Generation2 replaces generation:U32 with key:GKey, retains B3 state/root/inventory/rootAliases/operations/createdRevision, uses RRef for root/inventory and LocalID for operations. Every operation entry must name that operation's authorityGeneration; root/output inventories belong to key (validated alias evidence does not relax this). Its policy RRef equals PortableAuthority.policy. Authoritative epoch/roles/active must agree across this selected coordinator, AuthorityIndex and Binding; other preserved source manifests/catalogues are historical origin evidence, never competing active coordinators. Current membership may retain them as original records; only the explicit manifest selector confers coordination. No imported original role is a local activation grant. A file claiming two coordinators or mismatched selected role maps rejects.

PortableAuthority.writerSpace is an existing OriginSpace used for new profile-wide operation/task/coordinator identities; it names no key. Initial native profile uses its own space. On explicit import with fewer than16 namespaces, allocate one destination-origin namespace T if the complete post-import graph and reserved byte/count credits fit; otherwise refuse capacity before admitting the candidate. T uses the new destination's original profile/wallet IDs and is then fixed in writerSpace. If all16 namespaces are present, retain the imported, authenticated writerSpace T and append fresh main-generated logical IDs in T; no new space or rewrite of old T records is needed. This is a deterministic naming rule, not reuse of source grants, KP, nonces, sessions or physical IDs. Fresh physical profile/caller identity is still new, all imported binding entries remain imported=true, new entries are false, and collisions against current AND historical IDs are rejected before commit. Do not infer the writer from the first matching bare ID or silently alias S into T. Repeated restore at capacity uses the same authenticated logical writer namespace, preserving original byte commitments without unbounded namespace growth. Missing/unsupported writerSpace or exhausted actual byte/count/nonce credits fails explicitly, preserving complete source; it never evicts records to admit operations. Different writer selection is a semantic mutation reflected in coverage, not backup bookkeeping.

Import has two distinct authority snapshots. First validate the file's original PortableAuthority/selected coordinator and original coverage with its original roles, without exposing a live wallet. Then create fresh native coordinator/catalogue/candidate records in T for the destination head: active=null, every recovered generation candidate, physical admission=candidate, and epoch=source epoch+1 with checked overflow. The original coordinators/roles/records stay preserved evidence; the new selected Manifest2 and Binding role map agree on the inactive candidate state. One installation-level Candidate2 may inventory all16 generations; this does not create16 simultaneous preparation tasks. Candidate2.activationTarget names one exact recovered GKey and public identity for fresh consent. After validation and consent, activation sets that target active and all other recovered candidates retained in one commit, increasing epoch again. Source qualifications/roles/approvals cannot authorize that transition. A new current Policy record comes from the destination's independently recorded owner selections, or all-unselected when none exist; the imported Policy remains historical evidence and cannot select policy for the destination. Missing local choices prevent dependent activation/operations. New coordinator/policy/candidate/reservation capacity is reserved before import admission; any failure leaves the original file and prior local authority intact. File verification still reproduces the original hash before these legitimate destination semantic mutations. A later export describes the new selected coordinator and retains the original records/historical references without rewriting them.

## F13 — Snapshot coverage storage and membership

SnapshotBlob={schema:1,length:U32,digest:H,chunks:RRef[1..1024]}; length65537..67108864, digest=SHA256(exact concatenated data). Every chunk type is snapshot-support, never artifact-chunk. SnapshotSupport={schema:1,id:ID,owner:LocalID,ordinal:U32,data:bytes<=65536}; owner targets snapshot. All chunks except last exactly65536; nonempty last; unique ordinals0..n-1, sum length exact; max1024 chunks and64MiB as a refusal ceiling subordinate to F5's complete charged96MiB graph. The outer logical record remains <=1MiB. Inline coverageBytes uses <=65536, including exactly65536; length65537 always uses SnapshotBlob, not an inline exception up to1MiB. Both representations resolve exactly the same CoverageBytes semantics.

Support is derived, exclusive bookkeeping. A snapshot owns each snapshot-support chunk; no other snapshot, operation, observation, source entry, effect, output or semantic record may reference it. Traversal checks ALL inbound links and authoritative membership, including historical versions. Back-link owner matches the snapshot key and selected version's exact chunks; shared or unattached support rejects completeness. A changed snapshot version retaining the same immutable support is the same owner identity and must retain identical coverage bytes; no two different semantic pins reuse support. If identical bytes are needed as actual transaction/source/evidence, create a separate normal artifact-chunk with its normal semantic coverage and capacity charge. No content-based blanket exemption, reclassification or deduction is allowed. Duplicate bytes still cost their actual representation; only snapshot-exclusive derived support is excluded.

Coverage computation first validates exact membership/Ref digests and the F10 support ownership rule, then excludes snapshot, its support, derived backup/retirement/task bookkeeping and membership-page packing per F6. Their current-root selectors are excluded too. Membership still includes and authenticates these records for exact portable recovery. Pinning, adding support and updating physical/head/membership refs must not mutate semantic authority epoch/roles/coordinator fields. Snapshot.logicalRoots pins the pre-pin graph; source current records remain semantic roots through authority membership, not solely through snapshot. Candidate/qualified artifact metadata cannot smuggle unique custody into excluded support. Verify resolved support bytes exactly equal independently recomputed CoverageBytes for that immutable semantic snapshot, not merely supplied digest equality.

Preflight reserves worst-case snapshot/support/backup qualification count/bytes/nonce and staging credits BEFORE admitting an export. The64MiB support ceiling is not an allowance to exceed96MiB complete recovery or memory limits. Compute coverage by bounded streaming/memoizing to protected staging under the existing F5 budgets; if any bound/credit is unavailable, return CAPACITY_UNSUPPORTED without deleting source, altering pin membership or claiming complete backup. Every admitted graph must reserve enough credits for its required complete snapshot; this is tested at the maximum combined graph, not assumed from count alone. No full plaintext memory duplicate or unprotected temp file is permitted. Completed support is included in portable recovery, charged alongside Portable.coverage bytes, and authenticated exactly like other logical records, while excluded from semantic pairs only by the exclusive rule.

CL4-01 specifies lengths65535/65536/65537, first-ever large pin, support membership, export, qualification and one R-keep retirement without a repeated-backup loop. The15000 eligible-pair fixture has at least15000*77=1155000 bytes of pair material before selectors/framing, hence exceeds1MiB and requires SnapshotBlob. An independent encoder must compute its full actual length;1155000 is a lower bound, not a claimed complete vector. CL4-02 substitutes/shares/orphans support and checks refusal; then mutates one real transaction/source/effect chunk or owned output after qualification and requires staleness. CL4-03 round-trips complete large support offline, checks budget+1/failed writes/lost ACK at each pin/chunk/head/qualify barrier and confirms no source cleanup on failure. All UNEXECUTED; reopen and document arithmetic do not prove power-loss safety.

## F14 — Explicit freshness and exposure limits

Authenticated replay of the U head and its complete matching tree alone is also NOT shown detectable by an independently advancing P/L expectation: this proposal stores no such external freshness counter. The nonrollback assumption explicitly includes U even when current P/L/KP are not rolled back. MAC validation and crash ordering do not establish adversarial freshness. Whole valid P/U/KP/L rollback and isolated valid U replay remain separate negative controls; no nonce reuse or theft is claimed demonstrated by this limitation.

The expected security-claim result is NO promised detection; the independent review must not interpret a valid MAC as a freshness proof. Ordinary interrupted-write and missing/substituted-node cases remain required refusals under F8. CL-LIMIT-02 preserves an old encrypted export and its old credential, H-projection retained reconstructable content, R-keep retained keys, and E3 context-qualified scalar consequences; new passwords/deletion labels do not revoke those copies. These are future negative controls, UNEXECUTED. Selecting the limitation versus commissioning a separate stronger design remains an owner decision. No stronger freshness mechanism or forensic erasure promise is added.
