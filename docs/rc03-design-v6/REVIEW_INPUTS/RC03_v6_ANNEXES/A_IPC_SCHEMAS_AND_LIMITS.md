# Annex A — Closed IPC, admission and resource contract

Version `6.0.0-draft`. All behavior below is proposed, not implemented. Pending policy means `POLICY_PENDING`, never a default selection. [Specification](../RC03_TECHNICAL_SPEC_v6.md).

## A1 — Representation and shared grammar

The ordinary bridge exposes named functions only; each sends exactly one structured-clone object on a private, fixed channel. Main validates the received **values**, not an imagined JSON spelling. Integer `1000` and a JavaScript value originally written `1e3` are indistinguishable and have identical treatment. Duplicate textual keys must be rejected by a separate raw-file parser before constructing objects; no such claim is made about IPC. No JSON string is reparsed as a command. Reject unknown own properties, non-plain objects, accessors before cloning where detectable, inherited/symbol properties, cycles, sparse arrays, undefined, null except declared alternatives, functions, bigint, NaN, infinity, negative zero and binary types except those explicitly named. This is a value grammar; structured-clone implementation resource use precedes main's validation and needs packaged process limits, not a false preallocation guarantee.

Notation: `obj{...}` is a closed object; `oneof` is a discriminated union; `?` permits omission, never null; arrays have declared maxima. `ID` is 32 lowercase hexadecimal characters representing 16 random bytes; `H` is 64 lowercase hex; `U32` is integral number 0..4294967295; `U31` is 0..2147483647; `D64` is decimal string matching `0|[1-9][0-9]{0,19}` with value <=18446744073709551615. Revisions are nonzero D64. Monetary `Sat` uses D64 <=2100000000000000, preserving the existing base-unit interpretation; sum/fee arithmetic uses checked integer arithmetic, never floating XEC display amounts. `Network=oneof('xec-livenet','xec-testnet')`. Txid `H` is library `Transaction.id` display-order lowercase hex; convert exactly once at serialization boundaries, never accept ambiguous byte-order aliases. `Text(n)` is valid Unicode with no unpaired surrogate, at most n UTF-8 bytes, no implicit normalization of signed/message/password content. Human labels reject controls; secrets follow F3. `Handle=ID` is an opaque main table entry, not a key reference.

All requests: `obj{v:1,id:ID,method:Method,scope:Scope,args:Args[method]}`. `Scope` is `obj{kind:'profile'}` or `obj{kind:'wallet',profile:ID,wallet:ID,generation:U32,epoch:D64}`. Main resolves profile requests through its selected installation slot, never a renderer path. Every wallet method requires that exact catalogue entry; requests may inspect retained generations but cannot acquire new spending authority there. Results: `obj{v:1,id:ID,ok:true,value:Result[method]}` or `obj{v:1,id:ID,ok:false,error:obj{code:Error,correlation:ID,retry:'never'|'after-probe'|'same-id'|'after-consent'}}`. No free-form backend error, stack, key/path or secret detail. Invalid outer ID gets a main-generated correlation and no echoed body.

`Error` is closed: `PROTOCOL,SCHEMA,LIMIT,BUSY,POLICY_PENDING,STATE,UNAVAILABLE,LOCKED,CORRUPT,UNSUPPORTED,CONFLICT,CALLER_CHANGED,STALE,NOT_FOUND,APPROVAL_REQUIRED,APPROVAL_EXPIRED,CANCELLED,TIMEOUT,UNKNOWN_OUTCOME,OWNERSHIP_CONFLICT,INSUFFICIENT_FUNDS,AUTHORIZATION,RECOVERY_INCOMPLETE,ARTIFACT_STALE,REPLAY_CONFLICT,UNSUPPORTED_WORKFLOW,CAPACITY_UNSUPPORTED,LOCAL_KEY_RETIREMENT_UNAVAILABLE,CONTENT_COMPACTION_UNAVAILABLE,RNG_UNAVAILABLE,KEY_USAGE_EXHAUSTED,PADDING_CAP,ALREADY_DISPLAYED,DISPLAY_UNKNOWN,CONFIRMATION_MISMATCH,SECRET_STAGE_LOST`. All methods admit common `PROTOCOL,SCHEMA,LIMIT,BUSY,CALLER_CHANGED,STATE,UNAVAILABLE,UNSUPPORTED,TIMEOUT`; rows add the only domain errors. TIMEOUT after submission is returned as UNKNOWN_OUTCOME with a stable operation/commit lookup through inspect, not permission to retry with a fresh identity.

Public closed results: `Status={state:State,profile?:ID,wallet?:ID,generation?:U32,epoch?:D64,pendingPolicy:Text(64)[<=64],reason?:Error}` (State in B1; policy strings from G5). `Prepared={handle:Handle,subject:ID,kind:'candidate'|'operation'|'backup'|'deletion'|'retirement'|'destruction'|'external'|'ceremony'|'migration',task:ID,expiresInMs:U32}`. `Progress={task:ID,subject:ID,kind:TaskKind,state:TaskState,detail:Detail,error:Error|null}` uses B7's closed tagged enums; state=complete is terminal success, unknown is not failure or permission to retry. `Page<T>={items:T[<=100],next?:Handle,snapshot:ID}`. `Address={address:Text(128),branch:0|1,index:U31}`. `Output={output:ID,txid:H,vout:U32,network:Network,satoshis:Sat,state:OutputState,address:Text(128),recoverable:boolean}` (OutputState E1). `OpView={operation:ID,state:OperationState,effects:{effect:ID,state:EffectState}[<=32],needsConsent:boolean}`. `CandidateView={candidate:ID,network:Network,state:CandidateState,outputCount:U32,quarantined:U32,ready:boolean}`. No result includes xpub, root fingerprint intended for secrecy, raw artifacts, private scalars or recovery credentials.

R6 public identity rule: record entity IDs exposed in Output/OpView/CandidateView/Prepared/Progress and used by A2 methods are the current physical Cell localId (or the explicitly recorded L-domain task ID), not bare origin logical IDs. They are main-scoped handles: lookup requires current physical profile/caller and type, then resolves the exact QID/Ref through Binding. Task/subject/operation/effect handles may not be interchanged. Public generation is physical local generation. Same logical ID in two spaces yields two different localIds; stale handles after fresh-profile restore reject. A public handle never selects a namespace or returns raw keys. The public/local versus original/logical distinction is preserved in stored Summary/RequestBinding provenance and never rewrites an immutable origin Intent. Ordinary input grammars do not gain QRef/QID arguments.

## A3 — Main-only inputs and projections

`ReceiptInput={observation:ID,adapter:ID,network:Network,receivedSequence:D64,envelope:bytes<=1048576}` is accepted only over the authenticated main-owned adapter channel, not public IPC. Decode existing wire schema with <=16 transactions, <=256 outputs, unique vouts, canonical transaction IDs; derive script/address and verify recipient and envelope authentication before E1 inventory admission. Reconciliation input is `ChainObservation={operation:ID,txid:H,adapter:ID,request:ID,result:'not-found'|'mempool'|'confirmed'|'conflict',blockHash?:H,height?:U32,observedSequence:D64}`; confirmed requires both block fields and independently validated adapter evidence. No boolean paid/spent from renderer is authoritative. Limits and C reducers apply.

Destination handles are produced by main parsing authenticated/public message links or owner-selected endpoint configuration; fields internal: `{id,canonicalUrl,purpose:'external'|'relay'|'registry'|'forum',sourceMessage?:H,epoch,caller,expiresMonotonic}`. Ordinary IPC cannot register an arbitrary URL. Parsed link existence grants no launch authority. A profileDraft handle is main-generated from the currently supported profile-entry parser, with a closed allowlist **relay URL metadata only in this version**; unsupported avatar/arbitrary entries return UNSUPPORTED before any signing. Registry publication resolves the same existing `constructRelayUrlMetadata` encoder. Forum accepts only existing text/reply/vote schema; offerings, arbitrary entry payloads and attachments are explicitly disabled pending a separately reviewed semantic schema. This restricts admissible workflows without changing a wire format; compatibility tests must show enabled workflows encode identically. No concealed generic effect-plan handle is accepted.

## A4 — Trusted channel and authorization

Pending surface alternatives: T1 dedicated fixed packaged approval/secret window with no ordinary content, no Node and a narrow separate preload; T2 OS-mediated ceremony that displays the same immutable main summary and supplies authenticated result binding. T2 is unavailable unless a specific provider demonstrably supplies this capability; a generic OS password/unlock prompt is insufficient. Both require trusted initiation distinguishable from an ordinary-renderer imitation, exact packaged resource/origin, focus ownership, accessibility/spoofing tests, no remote navigation and user-switch invalidation. No surface is selected here.

Only the registered trusted frame may call: `trusted.inspect {ceremony:ID}` -> `{ceremony,purpose,summary:Summary}`; `trusted.decide {ceremony:ID,decision:'accept'|'cancel'}` -> Progress; `trusted.secret {ceremony:ID,kind:'mnemonic'|'backup-credential',utf8:Uint8Array<=4096}` -> Progress; `trusted.pickFile {ceremony:ID,mode:'read-backup'|'write-backup'|'read-legacy-image'}` -> Progress (main OS dialog resolves path); `trusted.showMnemonic {ceremony:ID}` -> `{words:Text(4096)}` **only on selected trusted surface**, no ordinary result, clipboard disabled. Backup credential max1024 bytes; mnemonic validated separately. Common errors plus APPROVAL_EXPIRED,AUTHORIZATION,POLICY_PENDING,STALE,CANCELLED. Every method rechecks registered trusted frame and purpose; private secret response cannot be requested through public bridge. A8 adds trusted.showGeneratedCredential for the generated-backup branch only. Main stores no credentials in ceremony logs. T2 secret input uses provider channel instead of trusted.secret. Secret UI consumes only one bound ceremony at a time.

`Summary` is a closed union: create/import/activate `{purpose,candidate,network,newPublicIdentity,oldGeneration?:U32,retainedCount:U32}`; payment/message/publication `{purpose,operation,intentHash,network,recipients:[{publicTarget,amount:Sat}],fee:Sat,change:[{publicAddress,amount:Sat}],content:Text(65536),destinations:Text(2048)[<=32],effects:EffectKind[<=32]}`; backup `{purpose,scope:'complete-profile',coverage:H,credentialPolicy,displayDestination:Text(2048)}`; deletion/destruction/retirement `{purpose,scopeDigest:H,managed:Text(128)[<=128],excluded:Text(128)[<=128],unresolved:U32,irreversibleBoundary:Text(128)}`; external `{purpose:'external',canonicalUrl:Text(2048),externalNetworkWarning:true}`. Unshown/truncated fields cannot be approved: paginate trusted display with explicit end acknowledgement, or reject size. These are public intent details, never secrets except explicitly trusted mnemonic display.

Transaction/target counts follow C/A5 (16/32); all transaction amounts/fees and exact original content/URLs are shown, no hash-only approval. Public identity is the existing identity public key, never new derivation. maxAttempts/expiry must fit selected R-B limits, not a renderer request. Mnemonic generation must equal scope generation. Read-only display consumes its own purpose-bound record before revealing words only to the trusted frame; lost display acknowledgement is unknown and requires a fresh display ceremony. It cannot sign, export or change authority. Recovery grant is one delivery dispatch; continuation acceptance is a separate consent after exact artifact persistence, not inferred from original payment consent. Any field mutation invalidates summaryDigest/consume; changing caller, target, original generation or epoch cannot reuse it. Creation/import does not implicitly authorize mnemonic display. Acquire performs no source deletion/activation. Resume grants no expanded destruction scope and still requires D6 revalidation.

Main derives sender WebContents/window, main-frame process/routing IDs, committed origin, navigation/document epoch, application boot ID, selected installation/profile, live/focus state from events; payload claims are ignored. Recheck before ceremony, consume, sign and each dispatch. Approval binds these facts, purpose, exact intent/artifact/effect set, generation/epoch, selected-member revisions and nonce. 120s monotonic expiry, one use, durable consume; restart invalidates live grants. No general manifest revision binding that invalidates approval on unrelated receipts. C4 defines entirely separate restart authority. Missing owner decision blocks even correctly formed requests.

Summary field typing is exhaustive: purpose discriminants are `create,import,activate,payment,message,publication,backup,deletion,destruction,retirement,external,mnemonic-display,recovery-delivery,continuation-accept,acquire,destruction-resume,backup-generated-credential`, admitting only their row's fields. candidate/operation/ceremony are ID; intentHash/coverage/scopeDigest are H; network is Network; newPublicIdentity is validated compressed-secp256k1-Hex33; recipients and change are arrays of at most256 closed entries; publicTarget is a validated XEC address Text(128) or compressed-secp256k1-Hex33 according to purpose; publicAddress is a network-valid XEC address Text(128). credentialPolicy is `generated` or `passphrase` selected under F3. EffectKind is C2's closed enum. The purpose in trusted.inspect must equal summary.purpose; all undeclared fields reject. `compressed-secp256k1-Hex33` means exactly66 lowercase hexadecimal characters, prefix02/03 and a valid non-infinity secp256k1 point. Trusted requests use the same v/id/method/scope envelope as A1, with method in the six trusted names only (including A8 trusted.showGeneratedCredential); scope and ceremony are bound by main, not independent claims. Their results use A1's success/error envelope. trusted.showMnemonic additionally requires a separately confirmed mnemonic-display ceremony bound to the originating create/import/backup subject; trusted.secret's kind must match that ceremony's expected input stage. A signature approval never authorizes secret display.

All methods can also return LOCKED, CORRUPT, CONFLICT, STALE or POLICY_PENDING from shared scope/provider/admission checks. Any mutating method can return UNKNOWN_OUTCOME after a possibly submitted commit; its original request ID resolves through the durable request index or main-generated correlation, never an unbounded fresh retry. This shared rule is part of every row's error grammar, including first-profile preparations.

## A5 — Aggregate limits and fairness

Proposed acceptance limits, not selected device policy: request262144 bytes as bounded canonical value encoding; result1048576; depth16; total nodes8192; total strings131072 bytes; arrays only per grammar (100 public page). 32 accepted requests/second per window, burst64; 8 pending IPC per caller, 32 installation-wide; primary status/cancel reserved queue2 serviced within250ms outside OS stalls; deadline15s, probes30s. Reject before backend/KDF/signature; preload limits supplement, never replace main admission. Malformed caller flood may revoke that caller session without deleting durable state.

One preparation/import candidate per installation. F5's charged96MiB/65536-record/sixteen-generation complete graph,192MiB candidate and512MiB logical staging limits govern all methods jointly; older independent64MiB candidate/256MiB obligation promises are withdrawn in this proposal. Owner capacity choice remains pending. Per operation32effects/16transactions/256combined inputs+outputs, final bytes<=8MiB, lifetime64attempts across all effects and4MiB additional reserved evidence; each additional attempt consumes byte/count/nonce credits before dispatch. Replay never evicts to admit a payment and occupies this same complete-recovery charge. Count limits never override byte limits. One GiB authority and proposed2GiB physical reserve require actual backend amplification measurements, not assumed sufficiency. Capacity/nonce admission failure is typed and preserves source, uncertainty and all existing records. Status and cancellation retain the reserved queue; persistence-dependent settlement still fails explicitly if storage is unavailable.

Import/export: one active and one queued **installation-wide**; F5 total budgets include KDF, decoder and staging. Queue carries no plaintext secret. Work yields each<=64KiB or10ms; cancel records request promptly, stops at next safe boundary or terminates isolated crypto worker within2s, leaves no admitted candidate. In-flight OS writes resolve before cleanup. Existing obligations consume quota until safely retired; dead caller removes only volatile handles. Pagination uses immutable snapshot references; expiry releases snapshot pin after in-flight reads, never authority records. Wall-clock changes never extend grants; clock/boot discontinuity revokes. Old requests correlate through C3 durable mapping.

## A7 — Complete workflow and task closure

All enabled mutations persist one B7 Task and its Replay entry in the owning P/L atomic commit before returning Prepared/Progress. Task.id and subject ID are distinct; Prepared includes both. Read-only inspect/list/status do not create a task. retryProbe is a bounded read probe; it returns Status and settles within30s without creating authority. reconcile/observeReceipt use an existing or new exact observation task, never a spending grant. Every prepare method has the following common transitions: prepared -> awaiting-input if secret/file required -> awaiting-consent -> running -> complete; any pre-consume state may cancel/expire; uncertain submitted persistence/effect -> unknown; unavailable prerequisites -> paused or typed unavailable. Detail uses B7's subject-specific enum, not these states as an invented subject phase. Main checks all required owner policies before preparation.
