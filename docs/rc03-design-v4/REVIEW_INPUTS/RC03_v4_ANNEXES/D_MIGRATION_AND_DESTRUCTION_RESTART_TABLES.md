# Annex D — Acquisition, cleanup, deletion and surviving lifecycle evidence

Version `4.0.0-draft`; proposed only. [B](B_LIFECYCLE_REVISIONS_AND_COMMITS.md), [F](F_PROPOSED_CRYPTOGRAPHIC_FORMAT_AND_COMMITMENTS.md) and [G](G_DEPLOYMENT_TOOLCHAIN_AND_CRYPTOGRAPHY.md) supply commit, protection and deployment prerequisites.

## D1 — Migration admission and restart fencing

`Migration={schema:1,id:ID,profile:ID,mappingDigest:H,sourceSchema:U32,sourceInventory:InventoryPageRef[],sourceDigest:H,targetCandidate:ID,phase:'preliminary'|'draining'|'frozen'|'copying'|'verified'|'activated'|'cleanup'|'complete'|'paused'|'conflicting',fence:{kind:'offline-readonly'|'exclusive-source',boot:ID,lease:ID,sourceIdentity:H,drainSequence:U64,inventoryDigest:H},copyCursor:U64,protectedCommit:ID|null,deletions:DeletionRef[],quarantine:Ref[]}`. Source mapping is package/user-data/origin/partition/schema/namespace tuple from the selected deployment, never a renderer path. InventoryPage stores complete bounded raw record evidence plus source-key bytes/digest/class, not only spendable cache entries. All namespaces, including frozen/pending/stealth/orphaned/output-only/message-support records, are enumerated. Total inventory limits A5; too large means retained source and LIMIT, never filtered migration.

Fence proof is live, not a string resurrected from a journal. Every process start invalidates fence leases. Before freeze/copy/activation/cleanup: acquire installation lock; verify exact volume/file identities and mapping; reacquire accepted source exclusion; drain all cooperative writers with acknowledged writes; reopen enumeration; compare to recorded source state adjusted only by committed deletion intents. An old process's prior drain acknowledgement does not count after restart. Any unexpected new/modified/missing record, reappearing old writer, mapping change, unavailable namespace or unsupported version returns conflicting/unavailable, retains both stores and halts cleanup.

Two pending source isolation alternatives (G2): M-A acquisition from verified immutable read-only offline source image, immutable identity/content digest and complete inventory; source image retained, new authority in distinct profile, originals/residual copies explicitly outside cleanup until separately acquired exclusively. M-B same-profile exclusive acquisition holds enforceable native locks/ACL/process exclusion across **every source writer/namespace**, including old binaries, and prevents new files/writers. Merely a cooperative mutex or process list is insufficient. If package cannot demonstrate these guarantees M-B is unavailable. Neither policy can constrain an external copied wallet signing elsewhere; declare that limit. M-A cleanup may delete only the owned acquired image after recovery qualification, not assert deletion of inaccessible original files. No policy selected now.

| Boundary | Durable prior/result | Cancellation and restart |
|---|---|---|
| preliminary probe | No mutation; diagnostic inventory only | Retry complete probes; no automatic setup |
| preparation/drain | Authenticated migration intent, mapping and acknowledged writer drains | Precommit cancel preserves source; restart reacquires source proof |
| freeze | Complete raw inventory and current live fence, sync journal barrier | Crash requires refence/re-enumeration before reuse |
| protected copy chunk | Immutable protected candidate records + copy cursor under B4 | Resume by verifying exact copied records; missing uncommitted chunk recopied only from refenced source |
| descriptor validation | E validation results, quarantine preserved, root agreement | Any unresolved coverage blocks activation/cleanup; no scalar silently discarded |
| protected commit/activation | Atomic B4 head switch, migration journal and retained original provenance | Unknown -> B4 resolve; prior source or complete protected authority; never generic corruption for valid stages |
| projection | Derived public view only after committed head | Failed projection rebuilds, does not roll back protected authority |
| cleanup qualification | F6 current actual-byte recovery proof + refenced source + no unexpected change | Failure leaves legacy residue visibly cleanup-pending |
| deletion intent | `DeleteItem={sourceIdentity:H,key:bytes,digest:H,intentCommit:ID,state:'intent'|'removed'|'confirmed'}` committed before remove | Missing source matches only prior acknowledged intent; else conflict |
| physical logical delete | Await selected source backend delete(sync barrier) | Lost ACK -> exact key probe; absent with prior intent reconciles, unchanged present retry, changed present conflict |
| cursor/complete | Commit removal acknowledgement/cursor; completion enumerates all source keys | Lost cursor cannot erase accounting; unknown/new key blocks complete |

After activation cancellation is pause/recovery, never legacy authority reinstatement. Main preserves final complete independent recovery before any last-copy deletion. Offline/read-back tests alone do not prove power-loss safety. Source cleanup proceeds only under selected source backend barrier contract; unsupported browser-origin backend cannot be silently treated as native LevelDB.

## D2 — Retirement fence

`Retirement={schema:1,id:ID,profile:ID,generation:U32,expectedEpoch:U64,coverageDigest:H,qualification:ID,scopeRefs:Ref[],state:'prepared'|'approved'|'fenced'|'retired'|'blocked',commit:ID|null}`. Distinct from content deletion and whole-profile destruction. Candidate/active generation is never retired by ordinary history deletion. Require independently usable recovery for every required root/output/scalar and exact unresolved artifacts. If selected OD-02 policy blocks qualification with unresolved work, retirement blocks; inclusive backup choice still cannot discard local unresolved reservation/delivery accounting or release funds. Retained private signing keys may move to verified portable recovery only under explicit retention choice; local replay/reservation tombstones remain. Cannot retire a key needed for an enabled retained-operation delivery/signature path; delivery uses existing bytes only.

Hold authority writer lock and backup artifact stable read handle; recompute required semantic coverage from current head, verify exact artifact digest/authentication/complete offline validation, check no new quarantine, provider/fence/policy still valid, then approve exact scope. Immediately before irreversible retirement commit, repeat current coverage/evidence checks under same lock; artifact mutation/unavailable media blocks. Updates arriving while fenced are queued and applied afterward; a queued recovery-bearing receipt requires re-evaluation before retiring its generation. Lease expiry releases fence without deletion. Record durable retirement intent first, remove secrets only after resolved barrier and selected recovery qualification. Any uncertainty keeps source. Bookkeeping-only changes do not stale coverage (F6).

## D3 — Content deletion never spends

`ContentRetention={schema:1,profile:ID,generation:U32,message:H,outputs:Ref[],scalars:Ref[],descriptorEvidence:Ref[],operations:ID[],replay:Ref[],reservation:Ref[],policyDigest:H}`. `Tombstone={schema:1,id:ID,profile:ID,generation:U32,scope:'message'|'conversation'|'all-history',messages:H[],retention:Ref[],revision:U64,contentCursor:U64,state:'retained'|'tombstoned'|'removing'|'removed'|'partial',policyDigest:H}`. Large scopes use pages, not unbounded arrays; each page<=256KiB. Every message/dialog/conversation/clear-history/wipe-content route delegates to this service, which has **no signer, reservation-create, transaction-forward, broadcast or key-retirement capability**. Never call the current forwarding-before-delete path. No automatic consolidation.

1. Main computes exact retention from raw authority, including frozen/pending/output-only/incomplete-descriptor scalar fallback and existing delivery/replay state. Copy missing required evidence durably; if retention cannot be complete, return RECOVERY_INCOMPLETE and leave content.
2. One B4 commit creates retention references and tombstone membership. Required retention and tombstone are visible together. A failed/unknown commit forbids removal.
3. Remove content in bounded chunks only after resolved tombstone barrier; await backend delete, then commit cursor. Late duplicates check tombstone before projection. New valid monetary observation can be retained silently in protected inventory under existing receipt rules but cannot resurrect content or spend.
4. Restart reconciles tombstone/cursor against actual content. Partial failures report partial, never complete. Restoring an old backup into existing profile merges current tombstones and replay union before activation; conflicts block. A fresh profile without newer tombstones cannot infer deletions absent from that older artifact; document snapshot-time limitation and never claim global deletion propagation.

Pending deletion-policy alternatives: minimum recovery/replay metadata plus removal of content; or retain full content and mark hidden (explicitly weaker deletion privacy, same no-spend rule). Pending delivery alternative: retain exact pending encrypted artifact and suppress content; or block deletion until resolved. No option discards unresolved artifacts/reservations. Remote delete: disabled this contract, or a separately reviewed authenticated adapter action with its own trusted consent, durable exact request and uncertainty accounting; it must contain no spendable artifacts and cannot promise server erasure. Until selected, no remote action. A future remote protocol is not silently enabled by local deletion acceptance.

## D4 — Destruction evidence outside the deleted profile

Surviving domain: installation lifecycle database `L` and immutable DPAPI-wrapped random lifecycle key `KL`, separate from profile authority database `P` and profile root-wrapping key `KP`. L contains only installation/profile-slot identity, scope digests, phase/cursors and supersession links; no wallet keys, mnemonic, content, transaction bytes or password. KL cannot decrypt P. KL, its wrapped anchor and L are explicitly **excluded** from managed-profile destruction and shown in trusted scope. They survive to authenticate terminal evidence. If unavailable/corrupt, destruction completion is blocked, not guessed. No forensic erasure or entire-installation deletion promise. Removing L/anchor manually is outside managed operation and must not turn surviving residue into absence.

`LifeHead={schema:1,installation:ID,revision:U64,currentProfile:ID|null,slotEpoch:U64,records:LifeRef[],pending:ID|null}` authenticated per F1. `Destruction={schema:1,id:ID,installation:ID,profile:ID,slotEpoch:U64,scopeDigest:H,managed:[{storeId:ID,mappingDigest:H,kind:'authority'|'projection'|'legacy-owned'|'temp'|'credential-wrapper',status:'present'|'removing'|'absent'|'unavailable'}],excluded:Text(256)[<=128],phase:'prepared'|'approved'|'irreversible'|'removing'|'terminal'|'blocked'|'cancelled',cursor:U32,approvalSummary:H,terminal:ID|null}`. Store lists<=128; source file paths resolved from main mapping; no renderer path. Life records use atomic sync batches and B4 outcome resolution within L.

Whole-profile destruction requires current complete independently verified backup by this proposal; absence/quarantine/unresolved policy blocks it. A request to destroy the last unrecoverable material requires a separate owner policy/design, not implied permission. The scope includes owned candidate/quarantine/migration/temp stores and profile KP wrapper; external exports, OS backup/swap/dumps/old residual copies remain excluded. No terminal with inaccessible managed store, even if key wrapper already absent.

| Phase/edge | Ordered action and crash result |
|---|---|
| prepare | L scope record committed; P unchanged; cancellation allowed |
| approve | Trusted full scope/current qualification consent; consumed approval saved L; cancellation still allowed |
| irreversible | Hold installation lock, drain P tasks, revoke all grants/subscriptions; commit L irreversible before first deletion; startup sees L first and blocks P use even if P still says ready |
| remove managed stores | For each store commit L remove-intent; logical remove using selected barrier; reconcile explicit absence; commit L cursor. P and KP may be removed only after this durable L intent. KL/L never in list |
| lost remove/cursor ACK | Reopen exact mapping: absent with prior intent -> account, unchanged present -> retry, replaced/unknown mapping -> blocked; never act on substituted directory |
| terminal | Reprobe every managed scope absent after selected barriers; one L commit sets terminal ID and slot destroyed; report logical managed-store deletion only |
| cancel after irreversible | Refuse cancellation; continue named recovery or report blocked. No profile reactivation |
| missing provider/anchor | Return locked/unavailable, preserve L/copies; no setup or completion |

Old copied terminal record cannot select a different installation/profile/slot: authentication/bindings fail. A full self-consistent restored L+anchor/profile set is not a detectable freshness attack under this local design; G claim boundary applies.

Explicit new-profile supersession: trusted request binds old terminal ID and current LifeHead revision. Commit L `Supersession={schema:1,id:ID,oldProfile:ID,terminal:ID,newProfile:ID,newSlotEpoch:U64,state:'prepared'|'committed'|'cancelled'}` before preparing new profile P2. P2 becomes a validated inactive candidate under new KP; old terminal remains intact. Atomic L commit changes currentProfile to P2 only when P2's bootstrap head is durably verified. Crash before L switch leaves old destroyed slot plus recoverable prepared successor; after L switch B classifies P2 candidate-only. Later B activation is separate. Cancel before switch keeps terminal and cleans only new candidate; after switch ordinary candidate cancel applies. Reducer follows authenticated current slot and supersession link, so old terminal neither becomes absence nor permanently blocks P2. Concurrent new-profile requests serialize, stale terminal/slot fails.
